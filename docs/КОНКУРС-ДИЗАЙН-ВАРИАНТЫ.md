# Конкурс раскладки: варианты под метками

*Метки разыграны маяком drand, round 31398210. Имена — в файле-ключе, который Автору смотреть не нужно до выбора.*

## ВАРИАНТ А

**Вывод:** Двухуровневый сценический экран: монолитный режим «Концерт» без переключения вкладок с крупными таргет-зонами (от 70dp) и XY-макропадом, совмещённый с вытягиваемой снизу шторкой «Инженер» для детальной рулёжки 15 параметров и сетки 4×16 в паузах.

### Схема экрана (Режим «Концерт», 1080×2400)

```
+---------------------------------------+
| [BYPASS / PANIC]   | REC | [04ms] VU  | 180px: Транспорт + задержка
+---------------------------------------+
|       E3  +4c  <<< [  |  ] >>>        | 220px: Строб-тюнер + строй 440
+---------------------------------------+
| [ P1 ] [ P2 ] [ P3 ] [ P4 ] [ P5-7 >] | 280px: Лента пресетов (педали)
+---------------------------------------+
| ГАРМОНИЯ: [ ON ] | Тональность: Am+5  | 260px: Быстрый тоггл и строй
+---------------------------------------+
|                                       | 760px: Назначаемый XY-пад
|         X/Y МАКРО-ТАЧПАД FX           |        (управление Space/Drive
|         + КНОПКА TAP TEMPO            |        на лету одним пальцем)
|                                       |
+---------------------------------------+
| ДРАМЫ: [ PLAY/STOP ] | 120 BPM | MUTE | 300px: Ритм-блок (пуск/сбивка)
+=======================================+
| ▲▲ ДЕТАЛИЗАЦИЯ: 15 РУЧЕК + СЕТКА 4x16 | 400px: Шторка Edit (саундчек)
+---------------------------------------+
```

### Ответы на подвопросы

1. **Иерархия и вкладки:** На сцене переключение вкладок фатально — скрытое состояние порождает ошибки и панику. Вкладки упразднены: всё критичное (Bypass, пресеты, тюнер, старт ритма) зафиксировано на одном экране. Детальная матрица 4×16 и 15 ручек вынесены в нижнюю шторку (Bottom Sheet), открываемую свайпом только для настройки.
2. **Плотность и 15 ручек:** Крутить микропотенциометры во время пения невозможно. В режиме «Концерт» эффекты управляются пресетами и сценическим XY-падом (назначается на 2 главных параметра, например, Reverb Mix / Echo Feedback). Внутри шторки ручки сгруппированы карточками по модулям (2×2) с шагом не менее 65dp.
3. **Живое исполнение:** Кнопки Bypass и пресетов увеличены до 80dp в высоту с контрастной цветовой индикацией активности (видно боковым зрением). Тюнер выполнен в виде стробоскопической полосы — не нужно вчитываться в цифры центов под софитами. Двойной тап по верхней панели мгновенно глушит тракт (Panic Mute).
4. **Слабое место:** Невозможно одновременно набивать паттерн драм-машины по сетке 4×16 и крутить частоту модулятора — редактирование паттерна требует открытой шторки.

**СВОЯ ИДЕЯ:** Использовать физические аппаратные кнопки громкости смартфона как сценический контроллер: одиночное нажатие `Vol+` переключает пресет вперёд по кругу, а удержание `Vol-` мгновенно активирует полный Bypass тракта без необходимости касаться экрана мокрыми руками.

  **Вывод: один экран без вкладок, разделённый не по категориям (голос/эффекты/барабаны), а по времени использования — «на сцене» против «до песни».**

  Вкладка — это скрытое состояние, а скрытое состояние нельзя проверить взглядом между фразами. Делить по категориям — ошибка оси: внутри одной песни нужны и гармонизатор, и эхо, и барабаны. Делить надо по «когда»: всё, что крутят в реальном времени, — на экране; всё, что настраивают заранее, — за одной кнопкой SETUP, куда на сцене не заходят.

  ```
  ┌────────────────────────────────┐
  │  A♯3   +4¢   (шрифт ~120px,   │ 220px тюнер: читается с метра,
  │  фон зелёный/красный)          │ цвет = в строю/нет
  │ ▶  ⏺  БАЙПАСС │ 12мс ▮▮▮▯ -6дБ│ 160px транспорт + индикация
  │ [1] [2] [3] [4] [5] [6] [7]   │ 140px пресеты, чипы 64dp+
  │ ДРАЙВ   ═══════╪══════  37    │ 4 макро-слайдера ×220px,
  │ ЭХО-ТАЙМ ════╪════════  1/8   │ назначаются на пресет
  │ ГАРМ-ГР ══════════╪═══  -3дБ  │ в SETUP
  │ РЕВЕРБ  ══════╪══════  22     │
  │ ▶ БАРАБАНЫ   120 BPM   гр ══╪═│ 200px
  │ [SETUP: все 15 ручек + сетка] │
  └────────────────────────────────┘
  ```

  Плотность: 15 ручек живому управлению не нужны — это проверяемое утверждение, а не вкус. Музыкант внутри песни трогает 2–4 параметра; какие именно — определяет аранжировка, значит, их можно назначить заранее на пресет. Макро-слайдер — полный ход ручки, цель 220px по вертикали: промахнуться мокрым пальцем некуда. Всё остальное (интервалы гармонизатора, сетка 4×16, тонкие ручки) — настройка, а не исполнение, и честно уезжает в SETUP.

  Живое исполнение: активные цели только крупные — пресеты, макро, транспорт, пуск барабанов. Мелкие цели на сцене отсутствуют физически, а не «аккуратно размещены». Обратная связь — немедленная: значение рядом со слайдером, тюнер цветом фона, байпасс инверсией всего экрана (нельзя не заметить, что тракт выключен).

  **СВОЯ ИДЕЯ:** раскладка должна доказывать себя данными, как ответ у нас на столе — журналом. Встроить счётчик касаний: после N репетиций элемент, который никто не трогал на сцене, автоматически предлагается к понижению в SETUP, а промахи фиксируются с координатами — через месяц экран перестроен по измерениям, а не по чьему-то мнению о дизайне. Ни у кого другого самопроверяющегося экрана не будет.

  Слабое место: подписи макро-слайдеров меняются от пресета к пресету — мышечная память ломается, и «третий слайдер слева» в разных песнях означает разное. Лечится дисциплиной (фиксированный порядок назначений), но само по себе не лечится.

## ВАРИАНТ В

РОЛЬ: фальсификатор · eyes: files (читал `MainActivity.kt`, не пересказ)

**Вывод: делить экран надо не по типу параметра, а по состоянию тракта — вкладки ГОЛОС/ЭФФЕКТЫ/БАРАБАНЫ это правильный ответ на неправильную ось.**

**1. Иерархия — от замера, а не от вкуса.** Два числа из живого кода. Ячейка драм-сетки: `dp(28)` в высоту и (360 − 52 метка − 24 паддинг)/16 ≈ **17 dp** в ширину (`MainActivity.kt:401-410`) — против 48×48 это в семь раз меньшая площадь цели. И все 15 ручек эффектов лежат в `wrapScroll` (`:329-354`), где `SeekBar` перехватывает вертикальный жест: попытка прокрутить список на сцене двигает случайный параметр. Оба дефекта не чинятся перестановкой блоков.

**2–3. Схема.** Живой режим (тракт запущен), 360×800 dp:

```
┌──────────────────────────────┐
│  A♯4   ├────●────┤   +7 ц    │ 140  тюнер + центы во всю ширину
│  ▁▂█▂▁  вход/выход   12.4 мс │      уровни и задержка одной строкой
├──────────────┬───────────────┤
│    BYPASS    │   ● ЗАПИСЬ    │  84
├──────────────┴───────────────┤
│ [ЧИСТО][ХОР][ЭХО][РОБОТ]…    │  96  7 пресетов, кегль 96×96
├──────────────┬───────────────┤
│  ЭХО ▮▮▮▮▯▯  │ РЕВЕРБ ▮▮▯▯▯▯ │
│              │               │ 192  4 «педали» 176×96: тап = вкл/выкл,
│ ДРАЙВ ▯▯▯▯▯▯ │ ГАРМОНИИ ▮▮▮▮▯│      свайп по всей плитке = глубина
├──────────────┴───────────────┤
│  БАРАБАНЫ ▶  100 BPM  ●○○○   │  96

Режим настройки — нынешние три вкладки со скроллом, сетка 4×16, все 15 ручек. Он и есть второй уровень.

**4. Плотность и промахи.** Спорю с обеими позициями затравки. По (а): вкладки в живом режиме — вред, в настроечном — благо; вопрос «вкладки или один экран» неразрешим, пока не разделены два разных занятия. По (б): спасение от промахов важнее плотности, и довод не эргономический, а акустический — **промах слышит зал, а недоступную ручку только ты**. Минимальная цель — 84 dp, прокрутки и тонких слайдеров нет, поэтому неточный тап физически не может сдвинуть параметр.

**5. Слабое место.** Свайп по плитке не показывает точное значение и не даёт точности; время эха в живом режиме недоступно вообще. Появляется режимность — но она привязана к слышимому состоянию, то есть не скрыта.

**СВОЯ ИДЕЯ:** аудио-регресс раскладки — писать выход тракта, пока `adb shell input tap` бьёт по случайным точкам живого экрана, и считать долю тапов, необратимо меняющих звук; целевое значение 0. Это измеряет не «удобно ли», а цену промаха.
