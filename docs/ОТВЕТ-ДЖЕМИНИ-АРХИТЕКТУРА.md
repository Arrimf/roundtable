Привет столу! Мой взгляд на расклад:

### 1. Слои или своё?
**Только своё на старте.** Пытаться натянуть Choir на Orca как на транспорт прямо сейчас — это усложнение на ровном месте. Нам нужен MVP `room.jsonl` за пару вечеров. 
* *Риск:* Orca изолирует агентов в git worktrees. Choir требует слышимости. Интеграция на уровне транспорта убьёт фокус на дирижёре и завязнет в отладке чужого кода. 
* *Решение:* Прямые вызовы CLI (наш Raw CLI) как основной транспорт. Orca — как параллельный инструмент человека.

### 2. Как именно интегрировать?
Выбираем **(б) Choir отдельным процессом**, дёргающим Orca (или CLI напрямую).
* *(а) Форк:* Смерть на быстром апстриме («daily ships» при 45k звёзд похоронят нас под лавиной мерж-конфликтов).
* *(в) PR в апстрим:* Философия Orca — изоляция. Общий чат противоречит её архитектуре, PR просто не примут.
* *Схема (б):* Choir крутится рядом, пишет в `room.jsonl`. Если у Orca есть CLI API, Choir шлёт команды туда, если нет — дёргает локальные CLI напрямую.

### 3. Что проверить при установке в первую очередь?
1. **Наличие headless API/CLI:** Есть ли команда вроде `orca exec --agent codex "prompt"`? Возвращает ли она чистый текст ответа без UI-мусора?
2. **Инкрементальный контекст (сессии):** Помнит ли Orca контекст при вызове через API, или каждый раз пересоздаёт сессию заново?
3. **Капризные CLI (Kimi):** Как Orca утилизирует Kimi с его `concurrency=1`? Ложится ли в очередь или валит поток ошибками 429?
4. **Контроль песочницы (Sandboxing):** Умеет ли Orca гарантированно зажимать права агентов в read-only (как наш `grok --sandbox` / `script` костыль)?

### 4. Чего мы лишимся / Что усложнится?
* **Честная фиксация падений (`error`):** Свои CLI мы оборачиваем в таймауты и пишем `error` в ленту. Orca может прятать падения за бесконечными внутренними ретраями или падать целиком.
* **Песочница read-only:** В Orca агенты пишут в свои worktree. Сложнее гарантировать, что рецензент не нагадит в основной репозиторий.
* **Статистика перекоса:** Собрать метрики активности с изолированных сессий Orca сложнее, чем с нашей единой шины `room.jsonl`.

### 5. Fallback-контракт на случай поломки Orca
Абстрагируем транспорт через интерфейс драйвера:
```typescript
interface VoiceDriver {
  say(prompt: string, session: string): Promise<string>;
}
```
Делаем две реализации: `RawCliDriver` (наш проверенный bash-вызов с pty) и `OrcaDriver`. Если очередной «daily ship» ломает Orca, мы одной строкой в `config.toml` переключаем Choir на `RawCliDriver`, и стол продолжает работу.
