## Вердикт стола — единогласно

**Ни одна из четырёх не является готовой комнатой для шестерых.**
Ядро прототипа — наш `live.py`; Orca — только транспорт/вьюер ленты,
не вторая база протокола.

| Кандидат | Что это на самом деле | Блокер для комнаты |
|---|---|---|
| Orca (`stablyai/orca`, 52 648★ на 2026-08-24) | ферма параллельных CLI-исполнителей, каждый в своём worktree | агенты не видят реплик друг друга; worktree-обязательность исключает HTTP-голоса (Gemini, DeepSeek) по конструкции |
| Hermes (`NousResearch/hermes-agent`, 235k★) | одиночный агент с субагентами-работниками | peer-to-peer нет; один бэкенд за раз |
| DeepSeek Harness (`dsh`, v0.1 preview) | харнес одного агента, «всё — плагин» | Agent Teams (roster, durable peer messages) существует, но private и исключён из релизов; иерархия, не стол равных |
| fusengine/harness (1★) | policy/hooks-слой для одного кодинг-агента | не рантайм вовсе; «не кандидат даже близко» |

Общие блокеры четвёрки: нет общей ленты, фаз/раундов, изоляции сбоя
участника, строгого «ПАС/упал/не звали», физического слепого барьера.

## Альтернативы, найденные голосами

- **AG2 `GroupChat`** (Кими; DeepSeek поддержал после ревизии) — единственный
  готовый примитив «комната»; брать как **эталон протокола**, не как боевой
  транспорт (участники там — API, не CLI-нити).
- LangGraph `StateGraph` (Gemini), OpenClaw (Grok), Hermes Kanban (Codex) —
  поддержки стола не получили.

## Главные риски выбранного пути

1. **Две истины**: `live.jsonl` против `orchestration.db` Orca. Канон —
   только `live.jsonl`; Orca не должна вести второй журнал.
2. **Слепота без границы доверия ОС**: механизм не выбран —
   commit-reveal (`sha256(reply+nonce)`) или отдельные UID/контейнеры.
3. **HTTP-голоса**: любой транспорт, требующий worktree/файлов, отсекает
   Gemini и DeepSeek по конструкции («тест безрукого голоса», Claude).

## Тесты для прототипа (уникальные идеи голосов)

- crash-drill: убить третий голос между ответом и публикацией (Codex);
- red-team слепоты: nonce + шестой голос ищет чужое в `/proc/*/fd` (Codex);
- «пустая комната»: 6 no-op × 100 сообщений (DeepSeek);
- readonly-обход `orchestration.db`: каких полей комнаты нет (Grok);
- пин коммита + дата доступа для каждой репозиторной претензии (Kimi).
