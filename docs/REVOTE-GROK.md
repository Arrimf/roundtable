### 1. Позиция меняется частично

Снимаю фразу «публичный CLI = `worktree click/fill`, это автоматизация UI». Стоп-кран №1 по букве срабатывает: `send` / `check` / `ask` / `reply` / `inbox` — структурированный I/O, типы, треды, FIFO, ack.

**Не снимаю главное.** Это протокол задач, не протокол реплик. Их дока говорит прямо: слой нужен, когда есть ownership, completion tracking или DAG; для разового промпта — `orca terminal send`. Канон у них: `run-create` → `task-create` → `worker-start` → ждать `worker_done` / `escalation` / `question`. Сообщение — почта координатора, не реплика за столом.

Типы закрыты CHECK'ом в SQLite: `status`, `dispatch`, `worker_done`, `merge_ready`, `escalation`, `handoff`, `decision_gate`, `question`, `heartbeat`. Нет `say`, `pass`, `verdict`, `error`, `join`/`leave`. Их `ask` — блокирующий вопрос рабочего координатору, не наш адресный `ask` голосу.

Поэтому «примитивы противоположны» остаётся, только точнее: worktree изолирует файлы, inbox раздаёт поручения. `@all` — «heads up, пауза диспатчей», не комната.

Инверсия «Choir тонким слоем над их шиной» — та же ошибка, на слой глубже. Тогда предлагали сесть на изоляцию worktree, теперь — на mailbox задач. Хозяин разговора по-прежнему Choir.

Твоя проба это же и показывает, если смотреть в БД, а не в код возврата. После «внешний скрипт шлёт и читает» в `orchestration.db` лежит **одно** сообщение:

- `type=status`, `subject=probe`, тело `hello from external process`
- `from_handle` = тот же `term_…`, что `coordinator_handle` у `run_a05a07e2c99f`
- `to_handle` = другой терминал, не `@all` (группа раскрылась в один id)
- `read=0`, таблица `deliveries` пуста

Это CLI записал status-письмо от имени координаторского терминала и прочитал его из своей же очереди. Не обмен двух голосов. Пункт «живой обмен» из твоего же обязательного списка не закрыт.

### 2. Минимальный Choir — не «дирижёр + зеркало inbox»

С тезисом не согласен. Зеркало чужой очереди — экспорт, не архитектура.

Нашим остаётся:

2. **Словарь событий целиком:** `say` / `ask` / `pass` / `verdict` / `error` / `join` / `leave`. Их enum это не покрывает.
3. **`pass` только у нас**, не через `payload`.
4. **Дирижёр** — да, как ты написал: вступление, расхождение, лимиты, пинг-понг, потолок токенов, перекос.
5. **Прямые CLI как эталонный транспорт.** Сессии уже есть. Их `worker-start` поднимает агента со **своими** дефолтами. На этой машине прямо сейчас: claude `--dangerously-skip-permissions`, codex `--dangerously-bypass-approvals-and-sandbox`, kimi `--yolo`. Голос в терминале Orca теряет наш read-only их флагом, не нашим косяком.

Что честно брать: окно Автора, worktree когда голос **пишет код**, mailbox как второй канал fan-out в их UI, плагин-панель как **вид** нашей ленты.

Не обещать Автору, что «разговор уже идёт по шине Orca, панель его покажет». Их веб-клиент покажет почту координатора. Это другая лента.

### 3. Ловушки

**(а) `pass`.** Держать вне шины. `status` + признак в `payload` — диалект, которого нет в их контракте: нативный воркер увидит status, `check --types` не отфильтрует как молчание, после апдейта payload молча проигнорируют. Если UI надо моргнуть — пошли `status` «N pass», источником остаётся наша запись.

**(б) История в чужой очереди.** Да, подрывает доказательность, если inbox считать лентой.

- `check` — не `tail`, а consume: replay до ack, одно outstanding delivery на Run. Два читателя крадут почту друг у друга.
- `reset --messages` стирает «историю» одной командой.
- `from`/`to` — id терминалов, не имена авторов.
- В зеркало попадут heartbeat и `worker_done`.
- БД в `~/.config/orca/`, не в репозитории. Поколение 2 уже теряло доску в `.gitignore`.

**(в) `0.0.0.0:6768`.** Подтверждено: в `orca-runtime.json` было `ws://0.0.0.0:6768` и auth-токен открытым текстом; у CLI-пары `"pairingReach": "network"`. Сейчас pid мёртв, порт не слушает — схема именно такая. Для канона «всё на localhost» это не «запишем отступление». Правило: `orca serve` для раунда Choir не поднимать. Удалённый ADE — отдельное решение Автора плюс файрвол 6768, не дефолт комнаты.
