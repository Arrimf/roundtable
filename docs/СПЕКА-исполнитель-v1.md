## Жизненный цикл

1. НАМЕРЕНИЕ → событие в ленту: act_id, исполнитель, файлы, зачем,
   эпоха, **base_sha** (была дыра: гейт сверял базу, которой в схеме
   не было — kimi).
2. АРЕНДА → lock-файл ~/.cache/choir/leases/lease-<act_id>.lock; flock держит
   ПРОЦЕСС ИСПОЛНИТЕЛЯ весь act (не окно — иначе ложная жизнь; не
   по-ходово — иначе ложная смерть между ходами; дыру нашёл grok).
   Файл создаётся ОДИН раз и не удаляется до закрытия act (два inode =
   две «живые» аренды — codex).
3. НАБЛЮДАТЕЛЬ ОКНА → нить с БЛОКИРУЮЩИМ flock на тот же файл:
   просыпается ровно в момент падения замка, без опроса (снимает «flock
   никого не будит» — codex, grok). Штатность различает НЕ замок, а
   событие: исполнитель пишет «close» в ленту ДО выхода; замок упал
   без close = вылет.
4. ЗАВИСАНИЕ ≠ смерть (deepseek): замок жив, а прогресса нет. Критерий:
   T минут без новых коммитов/изменений в worktree → окну жёлтый
   сигнал, Автору кнопка «отозвать» (событие + epoch bump + попытка
   kill pgid). Автоубийства нет — решение человека.
5. ПРАВКА → worktree, ветка act/<act_id>; сверка дифа с заявленными
   файлами — на ГЕЙТЕ (grok: сам диф ветки не видит запись мимо git —
   поэтому дополнительно пломба: journal_seal вокруг act расширяется
   файлом ref main, .git/refs/heads/main входит в пломбируемые пути).
6. РЕВИЗИЯ → диф в ленту; ревьюеры — все, кроме исполнителя; НЕ-CLI —
   текстом в промпт. Кворум: минимум 2 голоса, любой REFUTED блокирует
   до разбора. Доправка: НЕ полный сброс в livelock (kimi: канон
   «байт-в-байт = коммитить неисправленное») — повторная ревизия
   ТОЛЬКО ДЕЛЬТЫ доправки; финальное одобрение привязано к итоговому
   commit-sha.
7. ПРИЁМКА → гейт под flock: эпоха ∙ base_sha не сдвинут ∙ scope ∙
   одобрение на этот sha. Сдвиг main → rebase → ревизия дельты (codex:
   без этого параллельная приёмка вечно инвалидирует базу). Тройка
   sha: base = заявленный, patch = sha дифа base..head, result =
   sha merge-коммита; событие в ленту ПОСЛЕ move ref, проверка ДО.
   Авторство — --author голоса (kimi, из раунда).
8. СЛЕД РЕВИЗИИ — В ВЕЧНОЙ ИСТОРИИ (kimi: правило 4 — прежний план
   «удалить [no-review]» уносил след отказа в 644-кэш). Merge-коммит
   несёт трейлер Reviewed-by: <голоса|arr (emergency)>; гейт не
   принимает коммит без трейлера. [no-review] на пути стола не
   существует; аварийный путь — ревизия Автора, И ОНА ВИДНА В GIT.
9. ВЫЛЕТ → замок упал без close: событие «вылет», worktree в карантин,
   Автору диф + принять/продолжить/выкинуть. ПРИНЯТЬ из карантина
   (kimi: было невозможно по условиям гейта): явное событие Автора
   «adopt» СНИМАЕТ условие живой аренды — остальные проверки (scope,
   ревизия, база) в силе. ПРОДОЛЖИТЬ = новая аренда/эпоха НА ТОТ ЖЕ
   worktree, незакоммиченное сохраняется (grok: было «пусто»).
10. SWEEP периодический (kimi), закрывает только окно; Автор — явной
    командой-событием.

## Слепые фазы — механикой (grok: было обещанием)

Аренда НЕ ВЫДАЁТСЯ, пока в RUNNING есть акт слепой фазы; выдача
проверяет это в момент запроса. Идущая аренда при старте слепой фазы
получает жёлтый сигнал «merge заморожен до конца фазы» — гейт не
принимает, пока фаза открыта.

## Границы, названные честно

- Тот же uid: эпоха в ленте (644) переписываема, замки обходимы, push
  в main напрямую возможен. ВСЁ это — обнаружение (пломбы, эпоха,
  bare-remote как громкая дверь), не запрет. Единственный настоящий
  запрет уровня ОС — песочницы codex/grok.
- note-review сегодня привязан к файлам/24ч (канон) — гейт этапа 1
  вводит ДЛЯ ПУТИ СТОЛА привязку к sha; канонная привязка для ручных
  коммитов Клода остаётся, два пути не смешиваются.
- git checkout main неатомарен по файлам — истина ref; рабочая копия
  обновляется ff-only после merge (codex).
