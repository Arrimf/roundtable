Сначала прочитаю замысел Choir и разведку по Orca — отвечу по фактам из документов, не по README.Есть ещё архитектурный документ и онбординг — сверю их с тем, что Orca реально отдаёт наружу по API.Сверю поверхность Orca: плагины, CLI и есть ли API реплик — от этого зависит, транспорт это или только оболочка.Предложение Клода — ошибка в месте шва. Не «или-или», но и не «Choir тонким слоем поверх Orca». Orca — оболочка человека и изолятор процессов. Транспорт разговора — это `room.jsonl` + адаптеры к родным CLI. Иначе мы снова получим посредника.

Ниже расхождение с разведкой, не уточнение.

---

### 1. Слои или своё?

**Третий путь: инвертировать стек.** Choir — хозяин разговора. Orca — необязательное окно Автора, не шина.

```
Orca (по желанию)  — worktree, терминалы, мобилка, панель-вид
        ↑ смотрит / встраивает
Choir (наше)       — room.jsonl + дирижёр + адаптеры
        ↓
CLI-агенты         — прямые вызовы, свои сессии, свои подписки
```

Почему «Choir поверх Orca как транспорт» ломает замысел:

- Примитив Orca — **изоляция** (свой worktree, свой терминал, своё состояние). Примитив Choir — **общая лента**. Это не два слоя одной задачи, а противоположные инварианты. Если каждый голос в своём worktree, `room.jsonl` либо размножается на N копий (потом merge), либо Choir снова пишет за всех — откат к поколению 1, где Клод был единственной шиной.
- Поколение 2 в Cursor_W сработало потому, что **участники пишут сами**. Транспорт через Orca почти наверняка вернёт посредника.
- Публичный CLI Orca — `worktree create / snapshot / click / fill`. Это автоматизация UI, не протокол реплик. Плагин умеет `terminal.sendText` (напечатать в чужой терминал) и слушает `agent.status.changed`. Структурированного «пошли текст → получи `say`/`pass`/`error`» в первоисточниках нет.
- Сессии у нас уже есть у каждого CLI (`codex exec resume`, `grok -c`, `kimi -c`). Это и есть транспорт. Orca здесь не экономит слой — подменяет его чужим жизненным циклом.

Что брать у Orca без стыда: окно Автора, worktree когда голос **пишет код**, а не говорит, мобильный компаньон, восстановление терминалов. Это продукт для человека, не для хора.

Риск своего транспорта: снова руками ловить pty Грока, concurrency=1 у Кими, обрывы. Это уже поймано и записано в `ЗАМЫСЕЛ.md`. Риск чужого — каждый daily ship меняет то, на чём висит стол.

### 2. Как именно интегрировать?

**(а) форк — нет.** У апстрима 8600+ коммитов и daily ships. Форк Electron-IDE ради панели «Комната» съест стол быстрее, чем родится дирижёр. Пожелание Автора — про то, **куда смотреть**, не про то, **кто владеет лентой**.

**(б) процесс рядом — да, но не как «дёргает Orca транспортом».** Choir живёт сам: `post` / `tail` / адаптеры. Orca в том же окне держит терминалы. Связь — файл журнала и, если повезёт, тонкий вид. Если программного API реплик нет (по README его и не обещают), строить Choir на `click`/`fill`/`terminal.sendText` нельзя: это не контракт, а эмуляция клавиатуры.

**(в) PR в апстрим — не зависимость.** Shared room противоречит их тезису («не мешают друг другу»). Красиво подарить позже плагин. Наш темп от их дорожной карты не зависит.

**(г) четвёртый путь, его нет в тройке: плагин-панель, не форк.** В `examples/plugins/hello-orca` уже есть ровно то, что хочет Автор: `contributes.panels` + `panel.html`, capability-gated (`workspace:read`, `terminal:send`, `notifications:show`, `events:subscribe`). Панель — **вид** ленты Choir (SSE/`tail` журнала), не движок. Движок снаружи. Плагин API v1 и будет ломаться — поэтому он обязан быть тонким. Это и есть честный ответ на «общий чат внутри Orca».

Порядок: сначала свой MVP (`room.jsonl` + один адаптер), потом панель-вид, и только если на установке всплывёт настоящий agent-RPC — пересмотреть транспорт. Не наоборот.

### 3. Что проверить на установке (факты, не README)

Пять пунктов, в этом порядке. Пока их нет — решение «берём как транспорт» не на чем стоять.

1. **Есть ли структурированный I/O агента?** Команда или событие вида «отправить реплику → получить текст ответа». Если есть только `terminal.sendText` + «агент running/idle» — Orca не транспорт. Это стоп-кран для схемы Клода.
2. **Worktree vs журнал.** Запустить трёх агентов на одном вопросе. Кто видит `Choir/room.jsonl`? Одна inode или три копии в трёх worktree? Кто коммитит журнал? Если копии — изоляция убивает первоисточник.
3. **Сессии и sandbox.** Orca сам владеет сессией CLI или наш `resume`/`-c` жив? Грок: есть ли `/dev/tty`, применяется ли Landlock, можно ли обернуть в `script -qec`? Если sandbox молча падает — рецензент снова пишет в репозиторий.
4. **Kimi как кастомный агент + concurrency=1.** Не устроит ли Orca веер и 429. Это наш уже пойманный лимит, не их.
5. **Плагин как канарейка UI.** Поставить `hello-orca`, открыть панель рядом с терминалами, пережить один апдейт Orca. Если панель отвалилась — «общий чат внутри Orca» на плагине хрупкий, и это надо знать до обещания Автору.

Дополнительно, не вместо: что уходит в телеметрию (`onorca.dev/docs/telemetry`). Журнал стола не должен утекать «анонимной статистикой».

### 4. Чего лишимся, если Orca станет транспортом

Не удобства — инвариантов практики.

| Инвариант | Что ломается |
|---|---|
| Прямая запись голосов | Снова посредник. Поколение 2 откатывается. |
| Read-only рецензентов | Worktree — полный чекаут на запись. Флаги sandbox CLI Orca может проглотить (у Грока это уже ловилось без pty). |
| Честный `error` | Orca ретраит, реконнектит, гибернирует. Надо отличать «думает» от «квота/auth». Иначе в ленте тишина или выдуманный успех. |
| Журнал-первоисточник | Две истории: `room.jsonl` и треды/сессии Orca. Провенанс снова «восстанавливаем вручную». |
| Журнал в git | Worktree изолирует и git. Коммит ленты из N деревьев — путаница, ради которой Choir как раз и не должен повторять `.gitignore` доски. |
| `pass` и цена молчания | У Orca нет «не вступать». Пинг = полный ход агента. Дирижёр либо дорогой, либо его нет. |
| Счётчик перекоса | Если видны только «агент закончил», нет `pass`/`error`/`verdict` — статистика врёт, оркестратор снова главный автор. |
| Одинаковый контекст всем | Fan-out «один промпт → пять worktree» даёт пять изолированных решений, не слышимость. Это их продукт, не наш. |

Коротко: забираем то, ради чего Choir затевался, и оставляем то, что и так умеет любой мультиплексор терминалов.

### 5. Fallback-контракт

Стол собирается **без Orca**. Это не запасной план, а определение системы.

- Контракт стола: `room.jsonl` + `choir post`/`choir tail` + прямые адаптеры CLI. Если Orca нет или лежит — раунд идёт как сейчас.
- Orca не держит единственную копию журнала. Журнал живёт в основном дереве репозитория, не внутри агентского worktree.
- Версию Orca пинить. Автообновление в середине раунда выключено. После апдейта — канарейка: `hello-orca` открывается и `choir tail` читает ленту.
- Сломался плагин или CLI Orca — человек смотрит в обычный терминал / нашу веб-ленту. Голоса не знают, что Orca существовал.
- Сломался запуск через Orca — адаптер падает на прямой CLI той же сессии (`resume`/`-c`). В ленте `error`, не тишина и не дописанный за упавшего ответ.
- Запрещено: единственный путь «послать реплику» = `click`/`fill`/`terminal.sendText`. Это не контракт.

---

**Итог.** Идея Артёма верна как «не пишите IDE». Предложение Клода неверно как «сделайте разговор тонким слоем над изолятором». Автор хочет общий чат **в том же окне** — это плагин-вид, после того как лента уже живёт сама. Комнату «чуточку допилить в Orca» нельзя не потому, что не хватает кнопок, а потому что у них другая задача.
