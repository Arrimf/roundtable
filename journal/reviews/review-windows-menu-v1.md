# Ревизия: монитор окон как выпадающее меню (2026-09-14)

Повод: Автор — «при нажатии на "окна" съезжает форматирование. мы можем
убрать кнопочку в конец и сделать выпадающий список для активных
сеансов?». Причина: панель со списком окон вставлялась в ту же
flex-строку `#feedtop`, что переключатели и вкладки, и строка
растягивалась на высоту списка (скриншот `win-before.png`).

Сделано (JS окна, `roundtable.py`, блок «МОНИТОР ОКОН»): кнопка
«🪟 окна ▾» в конце ряда вкладок; список — выпадающее меню
`position:absolute` поверх ленты; закрытие кликом мимо и Esc; путь
проекта — basename с полным путём в подсказке; время запуска —
локальное. Сервер не менялся.

Формат: мини-ревизия read-only по дифу (codex, deepseek, grok) плюс
построчная ревизия субагентом Claude на живом тестовом окне 8796.
Первый вызов grok упал по моей вине (`grok -p --sandbox read-only "$P"`:
`-p` требует промпт сразу за собой) — перезапущен как
`grok --sandbox read-only -p "$P"`; к этому моменту часть правок уже
лежала в живом файле, grok это заметил и ревьюил присланный диф.

## Ответы дословно

### codex (rc=0)

Вывод: есть ошибка узкой раскладки и реальная гонка загрузок; XSS и утечек обработчиков в показанном жизненном цикле нет.

- **Узкое окно — P2** ([6395](~/AiSandbox/RoundTable/roundtable.py:6395)): `min-width:26rem` побеждает меньший `max-width:90vw`. При `right:0` меню выходит влево; ограничение относительно viewport также не учитывает ширину ленты рядом с правой колонкой. `#viewtabs` без переноса дополнительно теснит содержимое. Нужны ограничение шириной доступной ленты и адаптивный минимум.
- **Гонка — P2** ([6401](~/AiSandbox/RoundTable/roundtable.py:6401)): открыть → закрыть → открыть до ответа. Оба запроса очищают панель **до** `await`, затем оба дописывают строки: получаются дубликаты и устаревшие окна. Таймер после остановки также конкурирует с открытием. Нужны номер поколения запроса и очистка непосредственно перед принятым рендером. Дефект существовал раньше.
- **Длинный список:** нет `max-height`/`overflow:auto`; нижние действия могут оказаться за видимой областью прокручиваемой ленты. `z-index:20` ограничен контекстом sticky `#feedtop` (`6`) и не отменяет обрезание предком `#feed`; повышение числа проблему не решит.

Обработчики документа устанавливаются однократно в IIFE. `textContent` и присваивание `title` безопасны. Клик «остановить», включая отмену `confirm`, доходит до `stopPropagation` панели; перерисовка не закрывает её. Поздний ответ также не открывает закрытое меню: `hidden` не меняется. Проверено статически, без браузера.

### deepseek (rc=0)

Основные ошибки: гонка fetch, ограничение z-index из-за вложенности в sticky, min-width на узких экранах.

1. **Гонка fetch**: `loadWindows()` не отменяет предыдущий запрос при повторном открытии — если ответы придут в разном порядке, старый может перезаписать свежий. Нужен `AbortController` или счётчик запросов.
2. **z-index**: панель `#winpanel` имеет `z-index:20`, но находится внутри `#feedtop` (sticky, `z-index:6`). Sticky с z-index создаёт stacking context, поэтому панель не поднимется выше 6 глобально и будет перекрыта правой колонкой с z-index >6. Следует вынести панель из sticky или поднять z-index родителя.
3. **Узкие окна**: `min-width:26rem` в сочетании с `right:0` при ширине viewport <26rem вызовет выход за левый край и горизонтальный скролл. Нужно убрать min-width или ограничить `max-width: calc(100vw - 2rem)`.
4. XSS отсутствует — везде используется `textContent`/`title`.
5. Утечек обработчиков нет при однократном вызове, но при повторной инициализации обработчики `document` будут дублироваться.


### grok (первый вызов rc=2 — ошибка аргументов; повтор rc=0)

Смотрю живой код вокруг «МОНИТОР ОКОН» и сверю его с дифом.Перечитываю актуальный фрагмент CSS — grep показал другую разметку, чем первый снимок.Главный дефект дифа: гонка `loadWindows` — панель чистится до `await`, без поколения/Abort, повторное открытие (или `setTimeout` после «остановить») даёт удвоенный или устаревший список.

**Ещё:**
- **UTC во времени:** `shortTime` режет `T(\d\d:\d\d)` из ISO — часы UTC без зоны; в `title` тот же сырой ISO.
- **Узкое окно:** `min-width:26rem` сильнее `max-width:min(44rem,90vw)`; при `overflow-y:auto` у `#feed` выпадашка обрезается слева. `right:0` у якоря у правого края ленты — ок, пока не клип.
- **z-index:** `20` внутри sticky `#feedtop` (`z-index:6`) — отдельный stacking context; над лентой хватает, над `#side` (позже в grid, `position:relative`) при геометрическом наложении спорный слой.
- **confirm → document click:** после OK/Cancel нативный диалог иногда отдаёт click на `document` → `closeWins` гасит меню само; `stopPropagation` на `#winpanel` это не ловит.
- **После stop:** `setTimeout(loadWindows,1500)` перетирает только что дописанный статус «остановлено».
- **XSS / утечки:** `textContent`/`title` безопасны; слушатели на `document` вешаются раз в IIFE — не утечка при каждом открытии.

*(В живом файле часть уже чинили: `wgen`, локальный `shortTime`, убрали авто-reload, смягчили ширину — ревью по присланному дифу.)*


### субагент Claude (построчно, read-only, с живым окном 8796)

1. `shortTime` резал часы из UTC-ISO — Автор увидел бы «10:10» вместо
   13:10; окна без карточки отдают локальную строку из ps, формат
   смешанный. Чинить через `new Date(t)` + `toLocaleTimeString`.
2. Esc в поле реплики: `msg.keydown` зовёт `abortAll` с confirm
   «Прервать ВСЕ идущие ходы?» — меню закрывалось И вылезал confirm.
   Слушать на фазе захвата, только при открытом меню.
3. Гонка двух `loadWindows`: чистка до `await`, дописывание после —
   список вдвое. Счётчик поколений, очистка после ответа.
4. Повторный клик по «остановить» — второй SIGTERM и шум; авто-reload
   через 1.5 с стирал ответ сервера.
5. `min-width:26rem` при узкой ленте — горизонтальная прокрутка `#feed`.
Где находок нет: экранирование `\d` в r-строке, клик по document,
`shortPath`, `hidden`, `setView`, тесты `replay.js`/`domstub.js`.

## Что сделано по находкам

- **Гонка загрузок** (codex, deepseek, grok, субагент) — поколение
  запроса `wgen`, панель чистится после ответа, рисует только последний.
  Проверено тройным кликом: 3 строки на 3 окна (было 6).
- **Время** (grok, субагент) — локальное `ru-RU`: «13:16» сегодня,
  «12.09 15:29» иначе; полная метка сервера в подсказке.
- **Esc** (субагент) — фаза захвата, только при открытом меню,
  `stopPropagation`+`preventDefault`. Проверено: Esc в textarea при
  открытом меню закрывает меню, `abortAll` не зовётся.
- **Ширина** (codex, deepseek, grok, субагент) — `width:max-content`,
  `max-width:calc(100vw - var(--sidew) - 3rem)`, `max-height:60vh;
  overflow:auto` (codex — длинный список). При 760px горизонтальной
  прокрутки ленты нет (`scrollWidth == clientWidth`).
- **«Остановить»** (субагент, grok) — кнопка гаснет после confirm,
  строка тускнеет, ответ сервера остаётся; авто-reload убран, свежий
  список — при следующем открытии.
- **Клик после confirm** (grok) — закрытие по цели клика
  (`ww.contains(e.target)`), `stopPropagation` убран.
- **z-index / правая колонка** (deepseek, grok) — не менялось: меню
  якорится к правому краю ленты и с колонкой геометрически не
  пересекается; на скриншотах при 1400 и 760 px перекрытий нет.
- **Дублирование обработчиков при повторной инициализации** (deepseek)
  — IIFE выполняется один раз; не менялось.

Тесты: voices_http 69/0, `replay.js` на живой странице — без ошибок,
скриншоты `win-open2.png`, `win-narrow.png`, `win-final.png`.
