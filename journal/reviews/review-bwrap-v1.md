# Ревизия: клетка bwrap для CLI голосов (2026-09-17)

Повод: раунд «стол-v3-изоляция» (порядок 4 → 5 → 1+2 → 3; первый
инструмент systemd-run, второй — bwrap). После cgroup на акт и канареек
Автор: «го». Обещания 1 (исполнитель пишет только в worktree) и 2
(рецензент не пишет) — механикой, а не словом CLI (правило 8.5).

Сделано:
- `RoundTable/jail.py` — `bwrap --ro-bind / / --dev /dev --proc /proc
  --tmpfs /tmp --die-with-parent`; rw точечно; `available()` (пробник
  под замком, False на 30 с, True навсегда; `CHOIR_RT_NO_BWRAP=1`
  выключает), `prefix()` (порядок: ro → rw → ro поверх rw → `--chdir`),
  `wrap()` → (команда, факт `jail`/`jail_sha`/`jail_why`), `STATE`
  (каталоги состояния CLI rw), `STATE_RO_DIRS`/`STATE_RO_FILES`
  (бинарь, хуки, настройки, ключи, `projects/*/memory` — ro поверх;
  отсутствующие каталоги закрыты пустым `/var/empty`), `OWN_SANDBOX`
  (codex не вкладываем).
- `executor_run.py` — кресло claude/kimi/grok/dsh в клетке: rw =
  worktree + `edits.codex_roots` (gitdir акта, objects, refs/heads/act
  и reflog); общий .git ro явно; gitfile `<wt>/.git` ro поверх rw;
  молчащий git при сборке → close error rc=-4 (fail-closed); факт в
  close, в т.ч. при «CLI не запустился».
- `merge_gate.py` — рецензенты claude, kimi, deepseek(dsh), gemini
  (адаптер) в клетке: rw только состояние CLI; пакет, cwd и общий .git
  проекта ro явно; codex/grok — `jail=own`; факт в `edit_review` и на
  отказах канала; `checks()`: `jail` кресла, `jail_reviews_none`, обе —
  мягкие причины, не блок.
- Окно: строка «🔒 клетка кресла» с `jail_sha`, метка ревизии
  «🔒»/«БЕЗ клетки»; `act_view` отдаёт `jail*`.
- `test/jail_test.sh` — 41 проверка с настоящим bwrap (SKIP честно,
  если нет); `executor_test.sh`/`gate_test.sh` — подменный HOME;
  `edit_test.sh` и сценарий «молчащий git» — без клетки (их стабы
  ломают именно то, что клетка запрещает). `chamber/CLAUDE.md` — раздел.

Живьём из клетки (одноразовые дешёвые вызовы, файл в /tmp «ответь ОК»):
claude fable 12 с «ОК»; kimi «ОК»; grok «ОК» (pty через `script`
работает); dsh «ОК» после открытия `profiles/` rw (первая попытка:
EROFS на `profiles/headless/cordis.yml`); gemini-http — не проверен:
503 у шлюза по всем 5 ключам в обе попытки. Пробник haiku в plan mode
отказался читать /tmp вне и внутри клетки одинаково — это поведение
модели, не клетки. Коммит в `act/` из клетки проходит; запись вне
worktree, в HOME, `refs/heads/main2`, `.git/config.x` — Read-only file
system; `git status/diff/log` на ro-репозитории работают.

Формат: мини-ревизия read-only (два круга: codex, grok, kimi, deepseek,
gemini-http; субагент построчно с прогоном тестов и пробниками bwrap).

## Круг 1 — записи

**codex — ОТКАЗ.** «[P1] Гонка отключает изоляцию: первый поток
выставляет `_AVAIL=False` перед запуском пробы, второй читает
промежуточное значение и запускает CLI без bwrap — воспроизведено.
[P1] Исполнитель может менять чужие акты и общую объектную базу: rw
целиком `refs/heads/act`, reflog и `objects`; акт A может переписать
ссылку акта B или удалить pack. [P2] Рецензент теряет Git-контекст
worktree под /tmp (gitdir вне cwd спрятан tmpfs). [P2] При таймауте
теряется факт изоляции (`**fact` нет в TimeoutExpired/OSError).»

**grok — ОТКАЗ.** «Факт клетки теряется там, где он нужнее всего
(таймаут рецензента; кресло — Popen не стартовал, `jail_fact` в close
не кладётся). Обещание 2 дырявое в постоянное состояние CLI: rw на
весь `~/.kimi-code`, а argv — `~/.kimi-code/bin/kimi`; у Клода то же с
`~/.claude` (hooks/settings). `jail=none` рецензента гейт не называет;
комментарий «HTTP-голоса сюда не приходят» — ложь, gemini идёт в
`_plain`. Ложный `_AVAIL` на всю жизнь окна. Тест: `packed-refs.lock`
в логе — побочный эффект git, не свойство клетки; `/tmp/scratch.txt`
на хосте; запись «лесом» под /tmp — CLI видит успех. Докстринг кресла
врёт («не песочница»).»

**deepseek — ОТКАЗ.** «state_dirs() передаёт в rw все конфиги и кэши
CLI, где могут лежать auth-данные — обещание не выполнено, тест прячет
это подменой HOME. jail=none рецензента нигде не проверяется. Без bwrap
ход идёт с полным доступом — откат без блокировки. Кэширование `_AVAIL`
на процесс. При ошибке `git rev-parse` ход идёт без клетки. checks()
не смотрит jail рецензентов — несимметрично и небезопасно.»

**kimi — ОДОБРЯЮ (с двумя обязательными поправками), 27/27 PASS
прогнал сам.** «Окно обещает `jail_sha`, но никогда его не покажет:
`act_view` собирает close по белому списку без `jail*`; факт `jail` из
`edit_review` в карточку не доходит. Тест рецензента проверяет не то:
ловушки под /tmp — tmpfs, `not leak.exists()` пройдёт при любой клетке
с `--tmpfs /tmp`; нужен путь вне /tmp, как `real_leak` в §2. Факт jail
теряется на отказах канала. Кресло без клетки при молчащем git —
fail-open; fail-closed безопаснее. Проверено и претензий нет: порядок
bind'ов, `codex_roots` создаёт каталоги refs, grok-рецензент
действительно `--sandbox read-only`, `--die-with-parent` и `killpg` не
конфликтуют.»

**gemini — отказ канала** (503 «high demand» по всем ключам, дважды).

**Субагент (построчно, прогнал тесты) — ОТКАЗ.** «Блок клетки в
`executor_run.py` разорвал чужой `if/else`: `else: log_path = leases/…`
пристёгнут к `if jail_fact == none` — без клетки и без окна
`log_path is None` → AttributeError (это и есть оба FAIL теста); из
окна с клеткой стенограф уезжает в `leases/`, которые уборка стирает —
вкладка «исполнитель» снова пустеет (регресс правки 2026-09-06).
STATE_RO защищает только существующее: `~/.claude/agents`, `commands`,
`rules` отсутствуют — клетка позволяет их СОЗДАТЬ (пробник:
`create_agents_rc=0`), следующая незаключённая сессия подхватит;
`projects/*/memory` rw — авто-память это инструкции будущим сессиям.
`executor_test`/`gate_test` идут через настоящий bwrap с НАСТОЯЩИМ HOME.
gemini и dsh живьём не проверены. Подписи «запись в HOME отбита» —
поглощена tmpfs, не отбита. Подтверждено пробниками: `killpg` по pgid
снимает bwrap и внуков; ro поверх rw — EROFS/EBUSY; `script` даёт pty;
`/dev/shm` rw; bind файла — запись на месте проходит, rename нет.»

(пустой файл как точка монтирования сломал бы разбор снаружи); всё под

## Круг 2 — что сделано

- gitfile `<wt>/.git` — ro поверх rw-worktree (`ro_after` в
  `executor_run`); тест: `echo gitdir: /nowhere > .git` → EROFS, файл
  цел. Для codex (`writable_roots`, своя песочница) та же дыра остаётся
  — записано долгом.
- `empty_dir()`: нет `/var/empty` — свой пустой каталог
  `~/.cache/choir/jail-empty` (0555); нет и его — защита не собирается,
  но и не молчит: `state_ro` без источника пропускает путь (граница).
- `projects/*/memory`: glob по родителю — проект БЕЗ памяти получает
  пустой ro-каталог на её место; тест.
- gemini `keys.txt`: адаптер его только читает (`load_keys`, позиция
  ротации — в `.rot_last_http`), ro верно — без изменений.
- `git status/diff/log` на ro-bind репозитории — проверено пробником,
  работают (index не переписывается, если не менялся).
- Fail-closed при молчащем git — и для codex: `main()` при молчащем git
  и так отказывает; повторный отказ в `_run` — симптом, оставлено.
- `executor_test.sh` сценарий «снесли .git из-под CLI» — без клетки
  (в клетке gitfile ro, снести нельзя — это проверяет `jail_test.sh`).
- dsh: ro — общий `profiles/node_modules` без glob; тест раскладки
  (субагент).
- close rc=-4 — без поля `jail` (CLI не запускался; субагент).
- Цена пустых каталогов в HOME — в границах докстринга и CLAUDE.md.
- `hooks-paths` Грока — в `STATE_RO_FILES`; тест раскладки (grok).
- `a.jail_fact` → close при прерывании обёртки (rc=-2); тест: SIGINT
  обёртке посреди `sleep` — close error с `jail=bwrap` (grok).
- `_cache_empty()` отказывает, если каталог не пуст; тест (grok).
- Карточка рисует `reasons_soft` строками «⚠ …» (grok).
