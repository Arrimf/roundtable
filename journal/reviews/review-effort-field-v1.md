# Ревизия: поле `effort` в записи ответа и снятие обрезки чужих ответов в витке (2026-10-06)

Решения Автора по раунду jev-v1 (2026-09-23): нулевой шаг — писать фактически переданное усилие;
«давай уберём лимиты» — обрезка `REBUT_QUOTE_LIMIT` 6000. Диф: `chamber/choir.py` (`effort_passed`,
`_env_int`, `REBUT_QUOTE_LIMIT` из среды с умолчанием 0, `PACKET_CAP` и статус `oversize`),
`chamber/live.py` (`effort_passed`, поле в `turn()` при любом исходе), `roundtable.py` (`slim`: effort,
packet_chars, packet_cap), `test/effort_field_test.py` (новый, 21), `publish.sh`.

Ревьюеры: codex (exec, read-only), deepseek-http, kimi (kimi-code/k3), субагент-ревьюер. Grok не звался:
его песочница 1.0.46 падает вне клетки, а клетка стола в этот раз не собиралась ради одного вызова.

## Учтено
- Поле `effort` только когда вызов собран и канал есть (после `available()`), и при любом исходе вызова —
  таймаут, квота, исключение (codex, kimi, субагент; в комнате — после try/except, перед `channel`/`model`).
- deepseek в комнате — `DEEPSEEK_EFFORT` из среды, как читает адаптер (субагент).
- `_env_int`: кривое/отрицательное значение → умолчание с предупреждением, не трасса (codex, deepseek, субагент).
- Джемини и пакеты витка без обрезки (субагент, п. 4): `PACKET_CAP["gemini"]=24000` — пакет больше потолка
  голосу НЕ отправляется, запись `status=oversize` с `packet_chars`/`packet_cap` (правило 4), квота не тратится;
  пакет всем один (правило 1). Переопределение — `CHOIR_PACKET_CAP_GEMINI`.
- `slim()` окна отдаёт `effort`, `packet_chars`, `packet_cap` в карточку раунда (субагент).
- Докстринг без `cmd_of`; тест не зовёт внешний `grok --version` (подменён `cli_version`).

## Не принято
- deepseek: «на пути `_fallback`/запасной gemini усилие пишется от исходной линии» — линии одного голоса
  (kimi main/alt, запасная модель gemini) получают одно и то же усилие: источник — константа голоса, не линии.
- субагент п. 7: тест `_quote` по исходнику оставлен (функция вложена в `cmd_rebut`), поведение покрыто
  проверкой `REBUT_QUOTE_LIMIT`; `fallback_first` без `effort` — безвредно, признано ревьюером.

## codex
Дефекты есть.

- **P2 — теряется усилие при таймауте и исключении:** [live.py:1759](~/AiSandbox/RoundTable/chamber/live.py:1759). Обработчики ниже создают новый `ev` без `effort`, в том числе после запуска процесса. Именно дорогие зависшие вызовы выпадают из измерения усилия. Подтверждено подменой `_run_capture`.

- **P2 — неверная переменная окружения ломает загрузку модуля:** [choir.py:417](~/AiSandbox/RoundTable/chamber/choir.py:417). Например, `CHOIR_REBUT_QUOTE_LIMIT=none` вызывает необработанный `ValueError` ещё до разбора команды; перестают работать даже `--help` и чтение журнала, которым обрезка не нужна.

- **P2 — намерение записывается как факт передачи:** [choir.py:1755](~/AiSandbox/RoundTable/chamber/choir.py:1755). `effort` заполняется до проверки `available()` и запуска. При отсутствующем CLI запись получает, например, `status="missing", effort="medium"`, хотя голосу ничего не передавали. Аналогично при отказе подготовки запуска. Для обещанной семантики нужно отличать запланированное усилие от действительно переданного.

## deepseek
дефекты есть

- live.py:1759 (`ev["effort"] = effort_passed(name)`): на пути `_fallback`/запасной gemini фактическая команда может исполняться не для `name`, а запись получает усилие исходной линии — поле обещает переданное усилие по правилу 8.5, но может врать. Нужно писать effort от фактически исполненной голосовой линии/fallback-имени.
- choir.py: REBUT_QUOTE_LIMIT = `int(os.environ.get("CHOIR_REBUT_QUOTE_LIMIT") or 0)`: нечисловое значение (`6000a`, `6000.5`) уронит импорт всего `choir.py` с traceback, т.к. разбор без перехвата ValueError.

## kimi
• Дочитаю `ask_one` и проверю читателей записей.

• **Дефекты есть.**

  Проверено по живым файлам; grep-инструмент на содержимое строк глючил (семь подряд вызовов вернули только список файлов), поэтому один пункт внизу помечен как недопроверенный.

  **Дефекты**

  1. **`chamber/live.py:1759` — главный.** `ev["effort"]` ставится только на успешном пути `turn()`. Ветки `except subprocess.TimeoutExpired` (live.py:1764–1781) и `except Exception` (1782–1793) создают `ev` заново — без `effort` (и без `elapsed_s`). Для советника усилия таймауты и сбои — самые ценные точки данных; поле молчит именно там, где оно нужнее всего. В choir этой дыры нет: `rec` создаётся один раз с полем и дальше только мутируется через `rec |=` (проверил весь хвост `ask_one` до возврата, включая quota-fallback — там новый `ask_one` честно перевычисляет `effort_passed`).

  2. **`chamber/choir.py:417` — `int(os.environ.get("CHOIR_REBUT_QUOTE_LIMIT") or 0)`** на мусорном значении (`CHOIR_REBUT_QUOTE_LIMIT=abc`) бросает ValueError при импорте модуля — падает не одна команда, а любой `import choir`. В том же проекте есть конвенция защищённого разбора: live.py:137–141 для `TURN_TIMEOUT` (try/except → умолчание + предупреждение в stderr). Здесь она нарушена.

  3. **`chamber/choir.py` (`ask_one`, ранний return при `status=missing`, ~1760–1763) против `chamber/live.py:1562`.** В choir запись «CLI не найден» уходит с `effort` — хотя голосу не передано ничего; в live тот же случай возвращается без поля. Мелочь, но по правилу 8.5 обещание «усилие, фактически переданное этим вызовом» в choir-ветке missing врёт, а два дирижёра расходятся.

  4. **Докстринг `effort_passed` в choir.py (~967–981)** ссылается на «cmd_of» — такой функции нет, argv строят лямбды `VOICES[name]["cmd"]`. Проект уже чинил ровно такой врущий комментарий (запись про stderr Джемини в этом же диффе-hunk'е рядом); новая ложь того же типа добавлена правкой.

  **Проверено, замечаний нет**

  - (а) Соответствие `effort_passed` реальному argv — полное в обоих файлах: claude→`CLAUDE_EFFORT` (та же застывшая копия, что и в argv); codex/grok→`_renv(...) or eff()` с учётом `EFFORT_OVERRIDE`; deepseek→`"max"`, gemini→`"high"`, kimi→None; в live codex→`CODEX_EFFORT or None` совпадает с `_codex_tune`. Суффиксы линий (`kimi-alt` и т.п.) корректно срезаются через `name.split("-")[0]`.
  - (е) `publish.sh:79` включает `effort_field_test.py`, и файл `test/effort_field_test.py` в репо существует.
  - `fallback_first` в choir копирует фиксированный набор ключей без `effort` — не потеря: обе линии одного голоса получают одинаковое значение.

  **Не допроверено**

  - (г) Читатели записей: `roundtable.py`, `catalog.py`, `edits.py`, `merge_gate.py`, `test/exec_argv_test.py`, `test/catalog_test.py` содержат слово «effort», но строки получить не удалось — вероятно, это предсуществующие использования (лестница усилий каталога, проверки argv), а не чтение нового поля журнала. `chamber/coverage.py`, `stol.py`, `draw_ui.py` в списке не значатся, т.е. поле не читают; строгой валидации схемы записей, которая споткнулась бы о новый ключ, по косвенным признакам нет, но дословно это не подтверждено.

## субагент-ревьюер (итоговый ответ)
**Дефекты есть.**
1. `chamber/live.py:462–480` (`effort_passed`) — deepseek в комнате помечен `None`, хотя усилие ему передаётся: адаптер читает `DEEPSEEK_EFFORT` (умолчание max), окно экспортирует её акту. Поле врёт «рычага нет».
2. `chamber/live.py:1764–1786` — ветки `TimeoutExpired` и `except Exception` создают `ev` без `effort`; при таймауте CLI был вызван с усилием — самые ценные точки для советника.
3. `chamber/choir.py:1753` — поле ставится до `available()` и до спавна: при `status=missing` запись утверждает «передано medium», а вызова не было; конвенции choir и live расходятся.
4. `chamber/choir.py:417` + `_quote` — умолчание 0 ломает Джемини на витках: gemini-http отбивается шлюзом от ~25 КБ, пакет витка при размерах jev-v1 — 50–90 КБ; голос не увидит виток и сожжёт квоту на повторах.
5. `chamber/choir.py:417` — `int(env or 0)`: кривое значение → ValueError при импорте; отрицательное молча = без лимита.
6. `roundtable.py:591` (`slim()`) — белый список полей карточки раунда без `effort`: поле пишется, в окне не видно.
7. Мелочи: докстринг ссылается на `cmd_of` — такой функции нет; тест проверяет `_quote` grep'ом по исходнику; `ask_one` в тесте зовёт `cli_version("grok")` → внешний `grok --version`; `fallback_first` не несёт `effort` — безвредно.
