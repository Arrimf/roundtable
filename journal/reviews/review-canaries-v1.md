# Ревизия: канарейки прав и слепоты (2026-09-17)

Повод: свод раунда «стол-v3-изоляция» — две «свои идеи» стола: канарейка
прав (kimi) и канарейка слепоты (голос claude). Автор: «systemd-run на
акт и канареек, го».

Сделано:
- `RoundTable/canary.py` — канарейка прав: перед креслом и перед веером
  ревизии окно раскладывает приманки `.rt-canary-<ключ>` в корень
  проекта (маска в `.git/info/exclude`), HOME, каталог worktree'ов и кэш
  стола; пломбы sha256+mtime+inode+size с владельцем-окном; по закрытии
  акта — сверка и событие `canary` в ленту (кресло — `of=chair` с
  эпохой, ревизия — `of=review`); гейт закрывает merge при нарушении
  ИСПОЛНИТЕЛЕМ, нарушение РЕЦЕНЗЕНТОМ называет отдельно, не блокируя;
  сироты (окно закрыто, spawn не удался) сверяются уборкой настоящим
  событием, чужое живое окно не трогается.
- `choir.py --canary VOICE` (окно: select 🐤 в строке раунда): в слепой
  фазе седьмой голос с диском ищет чужие ответы раунда — журналы,
  карантин, истории сессий CLI, /tmp, процессы; вердикт по первой строке
  (ровно «ЧИСТО» → слепота проверена; «НАЙДЕНО…» → found; иначе
  unclear); запись `role=canary` публикуется с фазой и не входит ни в
  ответы, ни в покрытие; цитаты чужого текста запрещены промптом — пути
  и хеши.

Формат: мини-ревизия read-only (codex, deepseek, grok, kimi; gemini
отпал — 503 у шлюза) + построчная субагентом Claude, два круга.

### deepseek (rc=0)

Ошибка: ревизионная канарейка прикрепляется к исходному акту и блокирует merge самого акта, хотя должна порочить только ревизию.

В `_spawn_review` окно ревизии получает `meta={"edit": act, "canary": ckey}`, а `_canary_check()` при закрытии этого окна вызывает `feed_append("canary", ..., act=edit_act)`, где `edit_act` — тот же `act`. Событие `canary` уходит в ленту с `act=<акт>` и `key=<акт>.review.<hex>`. Затем `merge_gate.act_state()` складывает последнее canary-событие текущей жизни акта в `st["canary"]`, не фильтруя ключ `.review.`. Если ревизор (read-only) или ложное срабатывание дали `status="broken"`, `checks()` добавляет причину «канарейка прав нарушена» и закрывает гейт исходного акта.

Это смешивает два разных обещания. Ревизионная канарейка должна влиять на доверие к ревизии/требовать пересмотра, но не на готовность кода к merge. Нужно либо не указывать `act=edit_act` для ревизионных канареек, либо в `act_state/checks` учитывать только ключи вида `<акт>.<эпоха>`, отбрасывая `.review.*`.


### grok (rc=0)

Читаю полный запрос и указанные файлы — это мини-ревизия, сначала сверю обещания с кодом.Сверяю интеграцию с гейтом, reap и слепой фазой — ищу расхождения с обещаниями, а не только диф.**Гейт берёт одну «свежую» `canary` на акт — чистая ревизия маскирует сломанное кресло, сломанная ревизия блокирует merge чужой правки.**

`act_state` пишет первую (новейшую) `canary` с `act=<правка>`. И кресло, и ревизия зовут `_canary_check(..., edit_act)` с одним `act`. Дальше `checks()` закрывает гейт только по этой одной записи.

Порядок в `reap`: сверка кресла → `_auto_review` (сломанная канарейка её не отменяет) → сверка ревизии. Если исполнитель тронул приманку, а рецензент нет — в ленте `broken`, затем `clean`, гейт видит `clean`. Обратно: индексатор на веере ревизии закрывает merge правки. Нужны все канарейки этой жизни; merge — только по ключу кресла `<акт>.<эпоха>`. Подделка `kind=canary` голосом не проходит (`author ∉ _CLOSE_AUTHORS`).

**Сироты.** Сверка только в `reap`. Закрытие окна забирает `RUNNING` без `check`; `sweep_orphan_acts` приманки не трогает. `~/.rt-canary-*` никто не подметает. Пустой `files` (все `OSError`) → `clean` 0/0. Кресло кладёт `ckey` в meta даже если `lay` вернул False.

**Приманка в корне.** Гейт смотрит `status -uno` — untracked не грязь. `publish.sh` корень не копирует. Exclude в `.git/info/exclude` — да, но тест проверяет `-uno`, поэтому маска не доказана: обычный `git status` без exclude покажет файл. Гонка актов: ключи разные, ок. `mtime`/`ino` ловят перепись и CoW; atime/relatime не при чём. Ложное «нарушено» — индексатор/бэкап, не чтение.

**Слепота.** В `room.jsonl` канарейка попадает с фазой, не раньше; 100 символов — улика, не дыра фазы. Дыра другая: `ask_one` без новой сессии. У grok/kimi нить = последняя сессия cwd; канарейка с `--cwd PROJECT` становится «последней», живая комната `-c` её подхватит. Промпт велит смотреть `~/.cache/choir`, где лежат чужие `.prompt` — ложное «НАЙДЕНО» при целой слепоте. Классификация: не `ЧИСТО` с первой строки → `found` (преамбула модели). `cli_version`/`prompt_sha` через `ask_one` — ок. `_canary_arg` в `cmd_ask`/`cmd_run` — ок.

**Окно.** `select#canary` не из localStorage. `/round` режет участника и `no_files`; пустой `voices` (все по умолчанию) + канарейка из пула — 400 нет, `choir` выйдет 2.

Ответ на ваш вопрос «а должна?» — по замыслу да, по коду нет.
  - Продолжение акта: первая canary в ленте — от прежней жизни, `id < oid` → обнуляется (merge_gate.py:267), canary текущей жизни теряется, гейт видит `None` и нарушение пропускает. Фильтр по `id > oid` надо делать *в цикле*, как у `reviews` (строка 266), а не после.
  - Подделка закрыта: фильтр `_CLOSE_AUTHORS` (merge_gate.py:221) стоит выше веток и режет чужие `canary` тоже — ок.

  **(а)** Сироты: при рестарте окна reap не выполняется, приманки в HOME/`~/.cache/choir/canary`/корне проекта остаются навсегда — чистить некому (нужна подметалка при старте окна по `*.canary.json` без живого акта). HOME — общий для всех актов и вообще всех процессов: индексатор/бэкап, тронувший файл, даст ложное broken (mtime/ino), причём его спишут на конкретный акт. `git clean -fdx` в корне проекта удалит приманку мимо exclude → «удалён». `rev-parse --git-common-dir` под subprocess без `check` — при не-git проекте молча пропуск, ок.

  **(в)** Утечки нет: rec канарейки в `held`, публикуется с фазой; ≤100 символов чужого — после закрытия фазы, допустимо. Но голос-канарейка — та же сессия CLI: если `ask_one` переиспользует сессию, найденное чужое осядет в его истории и может всплыть в его следующем ходе участником — стоит запускать канарейку в свежей сессии.
