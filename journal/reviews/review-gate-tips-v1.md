# Ревизия: подсказки кнопок гейта, отчёты ревизий в ленте (2026-09-16)

Повод: Автор — «а стол проверил твою правку? не вижу отчёта» и «кнопка
rebase+ревизия не выдаёт подсказку». Отчёты ревизий моих правок лежали
файлами в `journal/reviews/`, в ленту стола не попадали.

Сделано: подсказки (title) у кнопок карточки акта «Ревизия / Rebase +
ревизия», «Принять в main», «Adopt»; событие `review_note` — отчёт
ревизии правки Клода в ленте (текст-итог + запись целиком, свёрнуто);
`note-review --record <файл>` постит его сам после отметки ревизии;
три прошлых отчёта (стенограмма, продолжение/отброс, rebase перед
веером) выложены в ленту записями 864–866.

Формат: мини-ревизия read-only (codex, deepseek) + построчная субагентом.

## Ответы дословно

### codex (rc=0)

Есть два дефекта: теряется итог ревизии в окне; чтение `--record` может уронить утилиту.

- В [roundtable.py:5235](~/AiSandbox/RoundTable/roundtable.py:5235) регулярка совпадает с `ревизия правки Клода:`. Поэтому ветка сохранения полного `ev.text` недостижима для штатного `review_note`: исчезают ревьюер, вердикт, число дефектов и файлы. Для `review_note` добавляйте весь `ev.text`, регулярку оставьте для `edit_review`.
- В [note-review:114](~/.local/bin/note-review:114) `read_text()` расположен вне `try`: каталог, отсутствие прав или удаление файла между проверкой и чтением вызывают необработанное исключение уже после записи отметки. Несуществующий файл молча игнорируется.

Остальное: `esc(body)` безопасен в текстовом HTML-контексте; присваивание `.title` безопасно; Python-строка сырая (`r"""`). Корень Git здесь `~/AiSandbox`, путь к `RoundTable/chamber/live.py` верен. Отсутствие chamber вызывает тихий возврат, не падение.

60000 — символы, не байты: кириллица займёт около 120 КБ. Для редких отчётов приемлемо; лимита строки нет, но журнал перечитывается целиком и растёт.

### deepseek (rc=0)

Ошибки: неэкранированный `full_text` в ленте (XSS) и регулярка для `review_note`, теряющая текст после первого двоеточия.  
`body` в `add()` формируется из `ev.full_text` без `esc()`, в отличие от `ev.detail` — нужно `esc(ev.full_text)`. `title` через DOM property безопасен, не требует `esc`. Регулярку `/^(ревизия [^:]*:)/` надо применять только к `edit_review`; для `review_note` брать полный `ev.text`, иначе теряются вердикт/файлы. 60 КБ в `live.jsonl` допустимо, но раздувает ленту — лучше ограничить 10–20 КБ или хранить отдельно. Путь `RoundTable/chamber/live.py` без падения: early return. Однако в `feed_note` `Path(root)` в `relative_to` лучше заменить на `Path(root or ".")`, иначе упадёт при `--record` с пустым `root`.

свойством, esc(body), хук review-gate не трогает новых полей, отметка
пишется до поста в ленту.
1. Регулярка `/^(ревизия [^:]*:)/` съедала итог review_note — в ленте

2. Событие без project: окно с --project вне LEGACY_HOMES его не увидит;
   чужой CHOIR_EVENT_PROJECT из шелла кресла наследовался бы молча.
3. Не видно, в какой журнал легло (env тестового окна).
4. Тихий пропуск из чужого каталога.
Не блокеры: обрезка 60000 без пометки; record не в reviews.jsonl;
rstrip многоточия; рост live.jsonl.

## Что сделано по находкам

- **Регулярка** (codex, deepseek, субагент 1) — для review_note берётся
  весь текст события, регулярка только для edit_review.
- **read_text вне try** (codex) — в try, ошибка называется.
- **`Path(root)` при пустом root** (deepseek) — `root or "."`.
- **project события** (субагент 2) — CHOIR_EVENT_PROJECT = корень репо.
- **Журнал и тихий пропуск** (субагент 3, 4) — печатается путь ленты и
  причина пропуска.
- **Обрезка и record** (субагент) — потолок 40000 с пометкой и путём;
  record пишется и в reviews.jsonl.
- XSS в full_text (deepseek) — не подтверждено: body проходит esc().
- Рост ленты — принято как известная цена; отчёты редки.
