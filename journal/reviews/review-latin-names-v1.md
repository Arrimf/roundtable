## Ответы дословно

### codex (rc=0)

Найдены 3 дефекта/риска по предоставленному коду, в порядке опасности.

1. **`chamber/names.py`, `round_file`: `f"{prefix}{translit(round_name)}{ext}"`.** Разделители и `..` сохраняются: раунд `x/../../outside` даёт `SEED-x/../../outside.md`. В `choir.py` вызов `out.parent.mkdir(parents=True, exist_ok=True)` позволяет подготовить такой путь для записи вне каталога раундов. Это существовавший риск, который новый помощник сохраняет; наличие входной проверки из дифа неизвестно. **Фикс:** централизованно запрещать `/`, `\`, управляющие символы и проверять принадлежность итогового разрешённого пути каталогу раундов.

2. **`chamber/names.py`, `_TR` / `translit`: необратимые коллизии.** `ёлка` и `yolka`, `объект` и `обьект`, `й` и `ы` дают одинаковые имена; `Ё` и `YO` также совпадают. Разные журнальные идентификаторы раундов получают один файл: возможны перезапись затравки/свода либо отказ создания вопроса. Сама `ё` не теряется, но её представление неоднозначно. **Фикс:** добавлять стабильный суффикс от исходного имени с проверкой коллизий; для переименованных файлов хранить явное соответствие.

3. **`chamber/choir.py`, `find_round_file`: ранний `return p` и цикл `(fname, p.name)`.** При соседстве старого и нового файлов существующий путь внутри журнала возвращает старый, а поиск по имени в каталоге проекта предпочитает новый, не обнаруживая неоднозначность. `legacy_to_new` без префикса тоже может направить кириллическое имя на чужой латинский файл. **Фикс:** собирать оба кандидата на каждом уровне приоритета и отклонять неоднозначность.

`live.names` доступен благодаря показанному `import names`. В показанном списке `publish.sh` присутствуют `names.py` и `tables.json`; полноту 158 переименований диф не подтверждает.

### deepseek (rc=0)

Дефекты (по убыванию опасности):

1. `chamber/names.py`, `round_file()`: не экранирует `round_name` — символы `/`, `\`, `..`, `*`, `?`, `[` доходят до `Path`/`glob`. Грозит записью/чтением за пределами каталога раундов. Фикс: `if re.search(r'[/\\*?\[\]]|\.\.|^\.', round_name): raise ValueError("bad round")`.

2. `chamber/names.py`, `translit()`/`round_file()`: транслитерация неинъективна: `ь`/`ъ` удаляются, `е`/`э` обе `e`, `й`/`ы` обе `y`, латиница не экранируется — разные имена дают один файл, перезапись/подмена. Фикс: `return f"{prefix}{translit(round_name)}-{round_name.encode().hex()[:8]}{ext}"` и ту же формулу в `legacy_to_new`.

3. `chamber/choir.py`, `find_round_file()`: в каталоге проекта возвращает первого кандидата без проверки неоднозначности; если рядом старый и новый файлы, молча выбирает новый. Фикс: собрать own-кандидатов и вернуть только при `len == 1`, иначе как в общем поиске.

4. `chamber/dossier.py`, default out: `f"DOSSIER-{project.name}.md"` не транслитерирует `project.name` — кириллица/спецсимволы нарушают конвенцию. Фикс: `names.round_file("DOSSIER-", project.name)`.

Импорт `live.names` и список `publish.sh` — ок.


## Что сделано по находкам

1. **Разделители и `..` в имени раунда** (codex 1, deepseek 1) — принято:
   `names.round_file` отвергает `/`, `\`, управляющие символы, `*?[]`,
   компоненты `.`/`..` (`ValueError`); `legacy_to_new` берёт только basename.
2. **Транслитерация не взаимно-однозначна** (codex 2, deepseek 2) —
   принято как известная граница, без hex-суффикса: суффикс сделал бы
   имена нечитаемыми ради пары, которой в журнале нет (ё/yo, ь/ъ, й/ы);
   окно ограничивает имя раунда регуляркой, записано в docstring.
   Появится коллизия — добавим проверку при создании.
3. **`find_round_file`: старое и новое имя рядом** (codex 3, deepseek 3) —
   принято: в каталоге проекта собираются оба кандидата, два файла →
   `SystemExit` с перечислением; ранний `return p` оставлен только для
   пути внутри `journal/rounds/`, как и был.
4. **`dossier.py` без транслитерации** (deepseek 4) — принято:
   `names.round_file("DOSSIER-", project.name)`.

Тесты после правок: autoreview 54/0, voices_http 69/0, smoke 13 PASS ·
2 WARN (`SMOKE_LIVE=0`).
