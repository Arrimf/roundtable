## Ответы дословно (первый круг)


=================== codex
1. **roundtable.py, `_auto_review(): return` при отсутствии `close` или занятом резерве — акт остаётся без автоматической ревизии; фикс: сохранять ожидающую ревизию и повторять запуск после появления закрытия или освобождения резерва.** Заметка с предложением кнопки не выполняет требование «каждая правка ревьюится». По выдержкам повторного автоматического запуска нет; наличие гарантированного подхвата пачкой не показано. Саму возможность опережения `edit_close` reap-потоком подтвердить нельзя: отсутствуют порядок ожидания процесса и реализация `_close_act`.

2. **executor_run.py, `_autocommit(): git add -A` — коммит получает все неигнорируемые изменения дерева; фикс: проверять состав снимка, а при недопустимых файлах сохранять акт для разбирательства.** Сюда попадут случайные артефакты, удаления и изменения уже отслеживаемого мусора, даже если позже его добавили в `.gitignore`. Вложенный репозиторий может попасть как gitlink вместо ожидаемого содержимого; его внутренний `.git` обычно не коммитится. Симлинк сохраняется как ссылка, содержимое внешней цели не копируется. Поэтому запрет любых симлинков из этих выдержек не следует, а проверка неожиданных gitlink полезна.

3. **executor_run.py, автокоммит до `_close_act(status="error")` — предположение: изменения упавшего CLI сохранятся, но выпадут из дальнейшей ревизии; фикс: отделить сохранение результата от его готовности к приёмке.** Коммитить остатки при `rc≠0` допустимо как сохранение работы. Такой акт должен получить ревизию с явной отметкой ошибки, а приёмка — требовать разрешения ошибки. В показанном вызове `_auto_review` фильтра по `rc` нет; утверждать, что ошибочные акты точно пропускаются, нельзя без окружающего кода.

4. **executor_run.py / roundtable.py, `<aid>.chair.log` и приоритет `durable.exists()` — предположение: повторная эпоха покажет старую стенограмму; фикс: учитывать эпоху в имени и выборе лога либо явно сбрасывать файл при новом запуске.** Имя больше не содержит `epoch`; состав `stale` и режим открытия файла не представлены. Добавлять долговечный лог в обычную уборку закрытых аренд нельзя: это вернёт исходное исчезновение вкладки.

Общий резерв внутри `_spawn_review` защищён `RUN_LOCK`, но обработчик `/edit_review` не показан. Если он предварительно занимает тот же `"review"`, получит отказ собственного запуска; если только вызывает общий помощник, этой коллизии нет.

Снимок `head` в приведённом закрытии **обновляется после автокоммита**: `head = new_head`. Здесь заявленная поломка не подтверждается. Сверку в `merge_gate.checks()` оценить невозможно: её текста нет. Аналогично, назначение голосу авторства содержимого само по себе не подделка; отдельный committer обёртки точнее обозначил бы происхождение коммита.

JS: начальный `FEED_POS.stick=true` означает прокрутку вниз при первом вызове `setView('feed')`, но дефект зависит от инициализации. `logKind` вообще не использует `label`. Утечка слушателей зависит от повторного использования `pre`, видимость `newer` — от отсутствующего CSS.

=================== codex
Дефекты есть, по убыванию опасности:

1. **executor_run.py**, `_autocommit`: `meta, path = fields[i], fields[i + 1]; i += 2`. В `--raw -z` после метаданных R/C идут **два пути**; читается исходный, целевой становится следующими «метаданными», дальнейший разбор смещается. Секреты, симлинки и gitlink могут пройти фильтр. **Фикс:** добавить `--no-renames` либо корректно потреблять оба пути R/C и проверять целевой.

2. **roundtable.py**, `_spawn_review`: проверка `_STOPPING` под замком, затем `spawn()` вне него. Между ними shutdown может установить флаг и забрать `RUNNING`; новая ревизия останется вне списка завершаемых процессов. Batch-ветка вообще не проверяет флаг. **Фикс:** синхронизировать запуск и регистрацию процесса с shutdown в общем `spawn()`.

3. **roundtable.py**, `_auto_review`: `_spawn_review(...) is None` → позднее `_REVIEW_QUEUE.append(act)`. Текущая ревизия может завершиться и опустошить очередь между проверкой занятости и добавлением; добавленный акт зависнет без следующего события. **Фикс:** атомарно проверять занятость и ставить в очередь, обеспечив запуск обработчика при свободном веере.

4. **roundtable.py**, sweep: `lg.stem.split(".")[0] not in active`. Сравниваются ID актов окна с номерами правок; живые раунды вообще отсутствуют в `active`. Старый лог работающего процесса удаляется, дальнейшая запись может идти в недоступный через имя файл. **Фикс:** отдельно защищать ID из ключей `RUNNING`.

5. **executor_run.py**, `st2 = _git_at(...status...) or ""`. Ошибка Git превращается в пустой статус и `dirty=False`, позволяя авторевизию при неизвестном состоянии дерева. **Фикс:** сохранять неизвестность и явно блокировать авторевизию до успешной проверки.

6. **executor_run.py**, `rest = [f[3:] ...]`. Второе поле переименования в porcelain `-z` содержит только исходный путь; срез отбрасывает три символа имени, иногда всё поле. Проверка исключений становится неверной. **Фикс:** разбирать записи по статусу, потребляя дополнительное поле R/C.

`git reset -q -- ...` защищён от начального `-`; drain на `"queued"` возвращается, бесконечного цикла здесь нет.
=================== deepseek
Дефекты (по убыванию опасности):

1. executor_run.py, `_autocommit`: парсер `meta,path=fields[i],fields[i+1]; i+=2` не учитывает, что raw `-z` для R/C выдаёт `meta\0old\0new`. После переименования парсер рассинхронизируется: новый путь может не исключиться, gitlink/секрет может уехать в коммит. Фикс: `i += 3 if len(parts)>4 and parts[4][0] in "RC" else 2` и проверять оба пути.

2. roundtable.py, финализация спавна: `_drain_review_queue()` вызывается до снятия текущего ревью с `RUNNING`. Очередной акт видит дубль, `_auto_review` возвращает `queued` и кладёт акт обратно; после `RUNNING.pop(act_id, None)` дренаж никто не вызывает — очередь зависает. Фикс: вызвать `_drain_review_queue()` после удаления текущего `RUNNING`.

3. roundtable.py, `_spawn_review`/`_STOPPING`: проверка флага под `RUN_LOCK`, но `spawn` вызывается вне замка. Между проверкой и вставкой в `RUNNING` shutdown может поставить `_STOPPING` и очистить `RUNNING`, а `spawn` добавит уже необслуживаемый процесс. Фикс: в `spawn` при вставке в `RUNNING` под `RUN_LOCK` проверять `if _STOPPING: return None`.

4. roundtable.py, sweep `ACT_DIR/*.log`: `active={t.get("edit")...}` содержит номера правок, а `lg.stem.split(".")[0]` — id акта окна. Лог живого акта не защищён и при возрасте >14 дней может быть удалён. Фикс: проверять вхождение в `RUNNING`, а не в `active`.

5. executor_run.py, расчёт `dirty` после autocommit: `status --porcelain -z` для R/C даёт `new\0old`, а `rest=[f[3:]...]` режет второй путь без статусного префикса; возможна ложная грязь. Фикс: R/C разбирать отдельно, второй путь не обрезать.

6. roundtable.py, `_auto_review`: `checks()` и проверка `reviews` по `st` не под общим замком с резервированием ревью; состояние может смениться, давая неверный автозапуск/пропуск. Фикс: перечитывать `act_state`/`reviews` под резервированием ревью.

=================== kimi
• Дефекты есть — 5, по убыванию опасности.

  1. **`executor_run.py`, разбор `diff --cached --raw -z` (критично).** При переименовании запись — `meta\0old\0new\0`, три поля; парсер читает `meta, path = fields[i], fields[i+1]; i += 2` — `new` попадает в `meta` следующей итерации, всё дальше рассинхронизировано. Фикс: `if parts[4][:1] in "RC": i += 1; проверять и old, и new`.

  2. **`roundtable.py`, sweep `ACT_DIR/*.log`: ключ защиты мёртв.** `active = {t.get("edit")}` — это номера правок («37»), а `lg.stem.split(".")[0]` — ид акта окна (hex). Сравнение не совпадёт никогда: стенограф живого акта старше 14 дней (долгое молчащее кресло, mtime не трогается) будет удалён на ходу. Фикс: `active = set(RUNNING) | {str(t.get("edit")) ...}` — собирать и иды актов.

  3. **`roundtable.py`, `_auto_review` при `_STOPPING`.** `_spawn_review` честно вернёт None, но `_auto_review` тут же встаёт в `_REVIEW_QUEUE`, которую уже никто не дренирует — очередь копится после закрытия окна, лента врёт про «№N в очереди». Фикс: в `_auto_review` первой строкой `if _STOPPING: return "skipped"`.

  4. **`executor_run.py`, `status --porcelain -z` после автокоммита.** Переименование в `-z` даёт два поля (`XY new\0old\0`); у второго поля нет префикса, и `f[3:]` откусывает первые 3 символа старого пути — он не совпадёт с `excluded`, `dirty` останется True, ревизия честной ветки заблокируется. Фикс: при статусе `R`/`C` пропускать следующее поле.

  5. **`executor_run.py`, «всё исключено».** `_autocommit` возвращает `(None, excluded)`, когда коммитить нечего — вызывающий пишет «автокоммит не удался», хотя удался пустой результат; `dirty` остаётся True и вечно блокирует авторевизию пустой ветки. Фикс: третий статус «nothing-to-commit» → `dirty=False` без note об отказе.

  Мелочь вне списка: `merge_gate.checks()` без замка — рваное чтение при concurrent rebase, последствие — лишняя запись в ленте, не потеря данных.
