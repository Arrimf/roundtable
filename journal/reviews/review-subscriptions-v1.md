# Ревизия: подписки CLI в панели лимитов (2026-09-23)

Повод: наказ Автора — «у Кодекса закончилась подписка, а мы проморгали;
добавить на панельку справа, где лимиты, дату окончания подписок CLI».

Сделано: `collect_subscriptions()` рядом с лимитами (фоновая нить,
таймауты `_get_json`, без платных вызовов): Codex — JWT `auth.json`
(план, `chatgpt_subscription_active_until`, `last_checked`); Claude —
`/api/oauth/profile` (статус; дата продления не отдаётся — названо);
Grok — `/rest/subscriptions` (активная, `billingPeriodEnd` epoch/ISO,
tier, status); Kimi/DeepSeek/Gemini — `none` с причиной. `_sub_state`:
флаг провайдера сильнее даты; `ending` < 7 сут; naive-дата — UTC.
Окно: строка `.sub` под шкалой (textContent/title; красное ИСТЕКЛА,
жёлтое «до …», серое «нет»), «неизвестно» до первого замера.
Переход в `expired` — одна заметка в ленту. `test/subscriptions_test.py`
27/27; http 111, smoke 16, UI-тест лимитов ок. Живьём: codex —
expired 2026-09-15, план free; grok — active до 2026-10-18,
super_grok_lite; claude — max, active.

Формат: мини-ревизия read-only (grok, kimi, deepseek, gemini-http;
субагент построчно). **codex не звался** — его подписка и есть повод.

## Записи

**grok — ОТКАЗ.** «Разобранная дата глушит флаг: Codex plan=free и until в
будущем даёт active — строка «подписка: до … · free», а note —
«подписки нет»; Grok без ACTIVE, но с будущим billingPeriodEnd у записи
с максимальным modTime — тоже active. Пустой список подписок Грока —
expired, красное «ИСТЕКЛА» без даты, не «нет». Тест проверяет не то:
даты только из _iso (+00:00), ветка Z не прогоняется, epoch не
подаётся, free с будущей датой — нет, renderSub не вызывается. Нет поля
subscription до первого сбора — строка скрыта, не «неизвестно». Не баги:
Z снимается, epoch порогом как у лимитов, XSS нет, сеть в нити с
таймаутом 6 с, Claude без даты честно «активна». Переход в expired
уместно писать одной строкой ленты, звонок не нужен.»

**kimi — ОТКАЗ.** «Codex: plan=free + дата в будущем → active — противоречие
в одной строке; лечится приоритетом плана. Claude: trialing/past_due
уйдут в «ИСТЕКЛА», хотя жива — unknown для неизвестных, expired только
для canceled/incomplete_expired. Naive datetime в _sub_state — локальная
зона. Дыры в тесте: epoch grok, JWT без auth-раздела, фолбэк id_token →
access_token. renderSub без JS-теста. Чисто: XSS, сеть в фоне, ms/сек
эвристика, .cap есть в каждой строке, изоляция падений сборщика. Событие
в ленту при expired — стоит, один раз на переход, отдельной правкой.»

**deepseek — отказ канала:** `--no-stream`, 419 с без первого байта,
дедлайн 420 исчерпан (потолок первого байта намеренно не действует без
потока — весь бюджет ушёл одной молчащей попытке; записано долгом).

**gemini — отказ канала:** 503 у шлюза, затем 400 FAILED_PRECONDITION
«User location is not supported for the API use» на ключе #2 — ключ
региона, не квота.

**Субагент — не состоялся:** «API Error: 403 Request not allowed
(authentication_failed)» на модели claude-fable-5-1 — мой собственный
канал отказал субагенту; сессия потребовала /login.

## Что сделано

- Флаг провайдера сильнее даты (`active is False` → expired до разбора
  даты); Codex free без прошлой подписки — `none`; Grok пустой список —
  `none` (grok, kimi).
- Claude: active/trialing/past_due — жива; canceled/incomplete_expired/
  unpaid/expired — истекла; незнакомый статус — unknown (kimi).
- Naive-дата — UTC (kimi).
- Окно: до первого сбора — «подписка: неизвестно», не пустота (grok).
- Заметка в ленту при переходе в expired, один раз на процесс (grok,
  kimi).
- Тесты: флаг vs дата, «Z», naive, free с будущей датой, JWT без
  auth-раздела, epoch мс у grok, пустой список, past_due/weird у claude,
  одна заметка на переход — 22/22 (grok, kimi).

## Круг 2 — записи

**grok — ОТКАЗ.** «При plan==free в _sub_state уходит active=False, и
строка возвращает expired до даты — ветка «none» мёртвая: free без
until и free с датой в будущем оба дают «ИСТЕКЛА»; заметка «подписки
нет» ставится на всякий free, title спорит с красной строкой.
_SUB_STATE пишется даже если feed_append бросил — сбой записи переход
больше не повторит; на старте prev is None, так что уже истёкшая
подписка (тот самый повод) в ленту не попадает. past_due и trialing
схлопываются в active — оговорка ни в state, ни в note.»

**kimi — НЕ ПРИНЯТО.** «Мёртвая ветка free→none (главный дефект).
Заметка о переходе врёт при флапации: unknown после сбоя сети
записывается в _SUB_STATE, и следующий expired считается переходом.
Блокировка collect_limits: синхронные HTTP к Anthropic и Grok каждый
проход лимитов — нужен кэш с TTL (часы).»

**Субагент (построчно, прогон) — ОТКАЗ.** «st="none" недостижим —
проверено прогоном: free без даты → expired, free с будущей → expired;
тест принимает оба и дефект не ловит. Тест заметки проверяет копию
логики, а не collect_limits; `until[:10]` при числовом until — TypeError,
гасится except. active=True с датой в прошлом → expired: у Грока на
границе биллинга и у Codex со старым JWT — ложное «ИСТЕКЛА» с заметкой.
billingPeriodEnd строкой-числом не разбирается. Подтверждено: порядок
subscription после _LAST_GOOD верный, feed_append из нити безопасен
(flock), стабы _get_json работают, renderSub — textContent.»

## Круг 2 — что сделано

- billingPeriodEnd строкой-числом (субагент).
