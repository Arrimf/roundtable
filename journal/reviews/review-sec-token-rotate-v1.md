# Ревизия: кнопка «сменить токен» кресла секретаря (2026-10-08)

Повод: Автор, 2026-10-08: «Сменить можно, удалив файл… — тогда для этого
кнопочку. А в чём смысл токен каждый раз менять был?»
Ответ на вопрос (записан и в комментарий кода): токен на процесс окна был
самым дешёвым решением первой редакции — секрет не жил на диске дольше
окна. Угроза от этого не зависит: голос в клетке не видит реестр окон ни
так, ни так; цена — ввод после каждого перезапуска. Поэтому токен
постоянный, а смена — кнопкой.

Правка: `roundtable.py` — `_sec_token_current` (файл реестра читается на
каждой проверке под замком, последний годный при пропаже файла),
`rotate_sec_token` (flock между окнами, повторная сверка предъявленного
токена под замком, временный файл 0600 + rename), `POST /secretary/token`,
`_sec_refused` (общая заметка об отказе для /secretary и /secretary/token),
сверка токена байтами, печать токена только в терминал; JS — кнопка
«сменить токен», слушатель `storage`, проверка вкладки по полю, кнопка
отправки по id. `test/voices_http_test.sh` — третье окно без токена из
среды: 403 на неверный, 200 со сменой, 403 на прежний, лента без токена,
заметка об отказе.

Ревьюеры: субагент (построчно, read-only), grok-4.7 в клетке (вер1).
DeepSeek не звался: диф маленький, а его ответ на пакеты этого дня шёл
13–17 минут; две ревизии сошлись.

## Найдено и учтено

1. **Заметка в ленту до печати и ответа** (субагент): упади `feed_append`
   — соединение рвалось без ответа, файл уже сменён, новый токен не
   напечатан. Теперь печать → лента в try → ответ.
2. **Тексты обещали «этот браузер получит сам»** (субагент): localStorage
   привязан к адресу с портом — окна на других портах вводят заново.
   Подсказка и статус говорят это прямо.
3. **Вкладки одного окна расходились** (оба): проверка шла по токену из
   браузера, отправка — по полю; после смены в соседней вкладке
   отправка получала 403 и писала ложную тревогу в ленту. Проверка — по
   полю, поле обновляется событием `storage`.
4. **Отказ /secretary/token молчал** (оба): заметка в ленту, как у
   /secretary, общий `_sec_refused` с ограничением раз в 10 минут на
   клиента и путь.
5. **Кэш токена по mtime/размеру/inode** (оба): правку на месте не
   замечал, между потоками мог на миг принять отменённый. Кэш снят:
   файл в сорок байт читается на каждой проверке под замком.
6. **Две одновременные смены обе проходили** (grok): браузер проигравшей
   сохранял токен, которого в файле нет. Смены серийны (flock), токен
   сверяется ещё раз под замком.
7. **Токен в stdout окна** (grok): если stdout — файл (nohup.out в
   каталоге проекта), клетка прочла бы его. Токен печатается только в
   терминал; иначе — путь к файлу.
8. **Не-ASCII в заголовке ронял обработчик** (поймал новый тест):
   `hmac.compare_digest` на str с кириллицей бросает TypeError —
   сверка байтами.
9. Докстринг `_sec_token` («удалить файл и перезапустить») обновлён;
   «воскрешение» токена старта после удаления файла не происходит —
   берётся последний годный из файла (проверено тестом).

## Названо, не правится

- Окно, удалив файл, продолжает принимать последний годный токен до
  создания нового файла — удаление файла больше не способ смены, способ —
  кнопка.
- `token_ok` в GET /secretary — молчащий оракул проверки токена (так
  было и до правки); перебор token_hex(16) неосуществим; токен, вписанный
  Автором руками (от 8 символов), — его выбор.
- Проверка «/act anchor accepted» в стенде окна изредка падает по
  времени (дважды за день, не связана с этой правкой) — ожидание
  удлинено до 60 с, причина не найдена; названа как флак.
