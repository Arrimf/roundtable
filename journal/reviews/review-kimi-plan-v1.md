везде, полоски лимитов и сроки подписки; текущее кресло Кими оставить на

сроков подписки». Разведка: Kimi Code CLI 2.0.2, план Plus (регион
global, api.kimi.ai/coding/v1), провайдер `managed:kimi-code`, вход
`kimi login`, алиасы `kimi-code/k3`, `k3-256k`, `kimi-for-coding[-highspeed]`;

bearer — `~/.kimi-code/server.token`). Автор снял ключ `moonshotai`

## Записи

**kimi (по подписке, k3, 1-й раз рецензентом на новой линии) —
ДОПУСТИТЬ С ПРАВКАМИ.** «1. `catalog._discover_kimi` не повторяет
`_kimi_key`: берёт первого провайдера с `api_key: str`, sorted ставит
`managed:kimi-code` раньше — каталог звонит заглушке подписки или
пишет „ключа нет“. 2. `_lim_kimi`/`_sub_kimi` зовут снимок без проверки
входа — без входа каждые 300 с поднимается 180-МБ kimi web ради
заведомой ошибки; весь запуск под `_KIMI_PLAN_LOCK` (до ≈95 с).
3. TOCTOU порта: bearer из server.token отправляется тому, кто ответил на
healthz. 4. `_sub_kimi` кормит `_sub_state` датой сброса квоты — в
конце месяца „⚠ подписка до…“ ложно. 5. `clear_quota` нигде не зовётся —
обещание без механики. 6. `_kimi_line_model`: нечитаемый конфиг —
проверка алиаса молча отключена. 7. Сироты: terminate только лидера,
kill без wait. 8. `mark_quota` пишет неатомарно. Не дефект: `_fallback`,
`prompt0`, per-channel dict на повторе, фильтр others, годовщина, токен.»

**deepseek — ДОПУСТИТЬ С ПРАВКАМИ** (110 с). «1. `_sub_claude`: оценочная
дата в прошлом при active даёт expired/ending — поле state врёт (8.5).
2. `_kimi_key` пропускает всех `type == "kimi"` — может отбросить
настоящий ключ. 3. TOCTOU порта и сирота при `start_new_session`.
4. `_kimi_line_model` при пустом declared пропускает любой алиас. Не
дефект: рекурсия с `_fallback`, метки с TTL, утечки токена нет.»

**grok — ДОПУСТИТЬ С ПРАВКАМИ.** «Кресло при резерве запирает не ту
организацию: `executor_run.py:553` берёт свободные ворота всех линий, а
модель кресла — всегда подписка: раунд держит `managed_kimi-code`, кресло
берёт `moonshotai2` и всё равно бьёт в занятую подписку.
`catalog._discover_kimi` — первый со строковым ключом, это managed.
Поле `model` — шаблон линии, не argv: окно `k3-256k` в журнале остаётся
`kimi-code/k3`; раунд клеит хвост модели окна без проверки — на резерве
`moonshotai2/k3-256k`, статус error, повтор не стартует; нечитаемый
конфиг — любой алиас без предупреждения. Третья линия в одном ходе не
зовётся; в раунде повтор пишет „основная линия занята“ — это квота.
`_sub_state` даёт ending за 7 суток: у Клода вспыхивает каждый месяц,
у Кими последняя неделя окна. Порт отпускается до Popen; SIGKILL окна
минует finally. Не дефект: prompt0, per-channel, мёртвый резерв,
`mark_quota` без with исполняется, reserve в паре room, `_KIMI_PLAN_LOCK`,
токен не в stderr/ошибках.»

**Субагент (построчно, тесты прогнал) — ДОПУСТИТЬ С ПРАВКАМИ.**
«1. Проверка алиаса только у подписки: `model_re` пропускает `k3`, резерв

ревьюер на `kimi-code/k3`, а замок — первый свободный из всех линий.
4. `ending` от справочных дат у Кими и Клода. 5. `_discover_kimi` —
managed первым. 6. Первая попытка теряется до 300 символов detail.
7. killpg нужен. 8. Три FAIL http-теста в моём прогоне („уже отвечают:

## Что сделано

- `channels.resolve_alias` на ВСЕХ линиях (объявленный алиас или своя
  модель; нечитаемый конфиг — подписка своя модель); поле `model` в
  журнале — реальный `-m` (субагент 1, grok, deepseek 4, kimi 6).
- `channels.gates_for_model`: кресло и ревьюер берут замок линии
  своего алиаса (grok, субагент 3).
- `_sub_state(soft=True)` для оценки Claude и сброса квоты Kimi
  (kimi 4, deepseek 1, grok, субагент 4).
- `catalog._discover_kimi` пропускает `managed:*` и пустой ключ
  (kimi 1, grok, субагент 5); `_kimi_key` — только `managed:`, без
  `type` (deepseek 2).
- `kimi_plan_snapshot` без входа не поднимает kimi web (kimi 2); killpg
  всей группы + wait (kimi 7, deepseek 3, grok, субагент 7).
- `fallback_first` — первая попытка целиком (субагент 6); заметка
  «линия занята» не пишется при повторе (grok); `clear_quota` при
  удачном ходе по помеченной линии (kimi 5); `mark_quota` атомарно
  (kimi 8).
- Тесты +11 (resolve_alias, gates_for_model, soft-состояния, снимок без
  входа, каталог, атомарность).

Не сделано, названо: TOCTOU порта `kimi web` (kimi 3, deepseek, grok)
— окно локальное, bearer постоянный; проверка отпечатка процесса —
долг; третья линия в одном ходе (grok); задержка TTL (субагент 2);
**триггер резерва при реальном исчерпании подписки не воспроизведён**
— первое настоящее исчерпание покажет, как отвечает CLI, и по нему
дополнить `_status_of` (субагент 2); три FAIL http у субагента —
параллельный прогон на одном порту с моим (мой: 139/0).
