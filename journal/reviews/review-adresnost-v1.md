## Находки

### 1. Устав врёт про `@имя`, механика ловит упоминание где угодно
**Серьёзность: КРИТИЧНО** · `Choir/live.py:142`, `745–749`, `1317–1326`

Устав при `PEER` обещает: «строка, начинающаяся с `@имя`». `ADDRESS_RE.findall(text)` берёт `@` **в любом месте**, включая середину абзаца и `email@grok.com` → `grok`.

При включённой опции это платный ход «по адресу коллеги» и запуск/продолжение ветки. Правило 8.5: поле/обещание без механики.

**Как чинить:** якорь только на начало строки, например `(?m)^@([A-Za-z…]+\b)`; не считать адрес внутри токена вроде `user@host`; тест на mid-line / email / line-start.

### 2. Цепочка `@A → @B → @C` обходит «после ответа — только руки»
**Серьёзность: КРИТИЧНО** · `Choir/live.py:1607–1625`

Наказ: после ответа адресата слово только поднявшим руку, иначе ветка закрывается. В коде закрытие **не** срабатывает при `why == "по адресу коллеги"`:

```text
адресат пишет «@kimi …» → why="по адресу коллеги" → THREAD=id этой реплики → ход оплачивается
```

Старая ветка **без** note «ветка закрыта» переукореняется. Потолок `MAX_TURNS_WITHOUT_HUMAN` (проверка в начале цикла, `:1574`) **не обходится**, но семантика опции — да: болтовня до 6 платных ходов через `@`.

**Как чинить:** внутри открытой ветки новый `@` не открывать (текст остаётся текстом) **или** сначала закрывать старую note’ом и только потом открывать новую по явному правилу; в любом случае не считать цепочку «рукой».

### 3. Два адресата (`MAX_VOICES_PER_EVENT=2`): следующий ход смотрит только `says[-1]`
**Серьёзность: ВАЖНО** · `Choir/live.py:1589–1603`, `85`

`@grok @kimi` зовутся параллельно. Дальше `last = says[-1]` — кто позже в жеребьёвке публикации. `@` и смысл **первого** ответа для маршрутизации теряются: его адресный хвост не читается; при «тихом» last ветка закрывается, даже если у соседнего ответа был `@` или важный ход.

**Как чинить:** для `res` из одного hand_word смотреть все `say` (объединять адреса/руки) или запретить >1 адресата при `PEER` (`MAX=1` для peer).

### 4. `goal_notice()` на каждый `ask_one` — пакеты могут разойтись (правило 1)
**Серьёзность: ВАЖНО** · `Choir/choir.py:136–154`, `1167`, `1505`

Цель читается из `live.jsonl` **заново** в каждом `ask_one`. `packet_prefix` в seed — снимок на момент seed. `/goal` посреди раунда → разные голоса получают разный префикс, а журнал врёт, что пакет был один.

В комнате та же щель слабее: `current_goal()` только при `first=True` (`live.py:762–764`); смена цели посреди нити **не** попадает в дельту (`kind=goal` отфильтрован в `:812–813`). Голос с уже начатой нитью живёт со старой целью до `reset` — это надо хотя бы честно назвать в UI/уставе, сейчас читается как «цель у всех актуальная».

**Как чинить:** снимок цели один раз на раунд (в seed / локальная константа), всем бит-в-бит тот же; в комнате — либо пушить смену цели в дельту всем живым нитям, либо явно писать «цель фиксируется на первом ходе нити».

### 5. `/state.goal` по хвосту 512 КБ ≠ `live.current_goal()` по всей ленте
**Серьёзность: ВАЖНО** · `RoundTable/roundtable.py:286–307` vs `Choir/live.py:167–174`

**Как чинить:** как у `_room_quota` по `room.jsonl` — скан всего FEED / отдельный маленький файл состояния цели; либо писать goal-маркер периодически; UI и `current_goal` — один алгоритм.

### 6. `_status_of`: ложные `quota` / `auth` по подстрокам stderr
**Серьёзность: ВАЖНО** · `Choir/live.py:177–198`

При `rc != 0` достаточно `quota` / `429` / `403` / `authentication` в **любом** месте `err`. Примеры, которые уже срабатывают: путь `…/quota-reports/…`, URL `…/models/403/…`, `authentication failed for git`. Окно (`_room_quota`, `roundtable.py:1624–1642`) подхватит ложную квоту комнаты.

`out` в функцию передаётся и **не используется** — 429 только в stdout не станет `quota`.

**Как чинить:** якоря ближе к choir (целые фразы / JSON-поля), не голые `403`/`quota`; сканировать и `out`; тест на URL/path false positive.

### 7. Kimi 429 из логов сессии в комнате не читаются
**Серьёзность: ВАЖНО** · `Choir/choir.py:369+`, `1341+` vs `Choir/live.py` (нет `quota_probe`)

В раундах 429 Кими часто только в `kimi-code.log` при «успешном»/мутном rc. В `live.turn` этого зонда нет: квота комнаты для kimi будет `ok` / `timeout` / голый `error`. `_room_quota` по `live.jsonl` эту квоту не увидит.

#### 1. `RoundTable/roundtable.py:286–306` — Потеря цели при росте ленты больше 512 КБ
* **Серьёзность:** **ВАЖНО**
* **Проблема:** В `_last_goal()` чтение ограничено хвостом в 512 КБ (`f.seek(max(0, size - 512 * 1024))`). #### 3. `Choir/live.py:188–198` — Ложные срабатывания `_status_of` на числах 401/403/429 в stderr и пропуск Kimi
* **Серьёзность:** **ВАЖНО**
* **Проблема:**
  1. Поиск подстрок `401`, `403`, `429` через `any(k in low for k in ("401", "403", ...))` в неструктурированном `stderr` даёт ложные срабатывания: например, `PID 40382`, порт `4010`, хэш коммита `a403f...`, номер строки `line 429` или случайный URL в трейсе ошибочно классифицируют сбой как `auth` или `quota`.

* **Как чинить:**
