# Ревизия: затенение модуля names, AST-сторож (2026-09-16)

Повод: раунд «стол-v3-изоляция» (акт b191ad3c) упал на фазе затравки:
в `choir.cmd_run` локальный список голосов `names` затенил модуль имён
файлов `chamber/names.py` (`AttributeError: 'list' object has no
attribute 'round_file'`). Ошибка внесена переименованием 2026-09-10 и
не была поймана тестами: живой `run` в них подменён стабом. Раунд
перезапущен (акт 9f29100f), жребий сохранён (ведёт grok).

Сделано: `import names as fnames` в choir.py; тест-сторож. По ревизии —
`test/shadow_check.py` (AST: локальная привязка затеняет импорт, а в
функции зовётся `<имя>.<атрибут>`) по всем модулям стола в
autoreview_test; roundtable.py импортирует модуль имён напрямую (alias
fnames — сторож тут же поймал ту же ошибку в do_POST); мёртвый
`import names` в live.py убран.

Формат: мини-ревизия read-only (deepseek, kimi; codex без квоты) +
построчная субагентом Claude (с AST-проверщиком и pyflakes).

## Ответы дословно

### deepseek (rc=0)

Ошибка: статическая проверка покрывает только choir.py и только два вызова; live.py/roundtable.py не защищены. В live.py `import names` остаётся уязвимым, если есть локальная `names` (например, список голосов) — по диффу этого не видно, нужен AST/grep. Строковой проверки недостаточно: пропустит `names.<другой атрибут>`, `from names import ...` или затенение в live.py. Нужен pyflakes/ruff в CI (ловит переопределение импорта `names`), плюс AST-сторож на все chamber/*.py: импорт `names` и binding `names` в той же области. Alias fnames в choir.py корректен.


### kimi (rc=0)

• Проверю, где ещё `names` может быть затенён в трёх файлах.

• **ВЕРДИКТ: фикс верный, но строковый сторож узок; pyflakes этот класс бага не поймал бы — нужен AST-сторож.**

  - `choir.py` чист: голых `names.<атрибут>` не осталось; локальные `names` (1742, 2003, 2082, 2429, 2957, 4323) больше не конфликтуют.
  - `live.py`: затенения **сейчас нет** — модуль `names` (строка 58) импортирован, но внутри файла ни одного доступа `names.`; `roundtable.py` зовёт `live.names.round_file` (3565, 3603, 4453) — это атрибут модуля, локальные `names` его не трогают. Ловушка латентна: будущий вызов `names.*` внутри функции live.py упадёт так же.
  - Сторож ловит только `round_file`/`legacy_to_new` — новый `names.translit(...)` проскочит. Заменить на AST-проверку: функция, где `names` — параметр/присваивание, не должна содержать `names.<attr>` (покрыть choir.py и live.py).
  - pyflakes не нужен для этого: локальное затенение глобального импорта — легальный Python, он молчит; а F401 в live.py был бы ложным (реэкспорт через `live.names`).



### субагент Claude (построчно, read-only)

Диф механически верен; AST-проверщик на старой версии показывает ровно
два падающих места в cmd_run, на новой — ноль. live.py: `import names`
не используется внутри файла — ловушка для чистильщика импортов, потому
что roundtable.py зовёт `live.names.round_file`; pyflakes этот класс
ошибок не ловит (затенение — легальный Python); строковый сторож узок
(два имени, только choir.py). Рекомендация: AST-сторож по всем файлам,
roundtable.py — импорт напрямую. Побочные находки pyflakes: мёртвые
импорты `random`, `serial_gate` в live.py, мёртвые `ctl` в
roundtable.py и `rebased` в merge_gate.py — безвредно.
