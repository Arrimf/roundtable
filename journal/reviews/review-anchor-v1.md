## Записи

**deepseek — ДОПУСТИТЬ С ПРАВКАМИ** (490 с, ≈$0.03). «1. Ложный сигнал
монолога: `chain_mono` пропускает `continue` события не Автора — ответы
других голосов между якорными репликами не рвут цепочку. 2. Хрупкий
поиск в `_find_live`: подстрока `"id": N,` зависит от порядка ключей;
`_find_room` — ложные совпадения в тексте, проверка `r.get("id")`
спасает. 3. Несогласованный тип поля `anchor`: у ответа голоса —
строка, у реплики Автора и в жребии — словарь (8.5). 4. Гонка на
`_ANCHORED`: множество без замка, чтение в рабочих нитях. 5. `since =
id − 1`: если `read_events` отдаёт `>= since`, в контекст попадёт
событие до якоря. 6. Черновик с id=0 для `pick_voices`. Не дефект:
stopPropagation, anchorSent, потолок и ПАС, shlex.quote, возврат
live.py в тесте.»

**Субагент (построчно, тесты прогнал) — ДОПУСТИТЬ С ПРАВКАМИ.**
«1. `ask --anchor` с досье: контролёр идёт через `turn()` напрямую —
сессия сброшена, промпт без устава и блока, `session_fresh` врёт.
2. `anchor_targets` из черновика без `_cap_group`, при `--once --prefer`
реально зовётся `[prefer]` — поле врёт, `chain_mono` считает не того.
3. `anchor_fresh` не сбрасывает `origin`/`cursor`: у deepseek (память
из ленты) «нить заново» живёт один ход; `session_fresh` ставится
голосу без сессии и на `error`. 4. kimi с двумя линиями: `_ANCHORED`
на голос, сброс — на линию под воротами; второй ход на другой линии
идёт старой сессией. 5. `_find_live` без фильтра проекта — ручной адрес
чужого проекта уходит в пакет. 6. `choir.py` run: отказ pick из-за
якоря печатается как «маяк недоступен». 7. Заметка о монологе ложится
раньше реплики Автора. Не дефект: `id` первый ключ, кавычки в text
экранируются, `"id": 12,` ≠ `123`, на живой ленте 1050 строк 0 двойных
совпадений; `hand_word` после отказа зовёт второго «отсюда» верно;
`/round`: вопрос собран до проверки qfile, sha сходится, `aflag`,
`lot_pool`; JS: capture-preventDefault гасит `<details>`, `MSG_PH` —
const до клика, `esc()` на адресе; HTTP-тест: `mv` выполняется всегда.»

## Что сделано

- Сброс нити — ОДИН раз на голос за акт, по ВСЕМ линиям, на диске, в
  `deliver` до сборки промпта; `turn()` только читает состояние
  (`anchored_state`) и пишет факты. Закрывает субагент 1 (контролёр
  досье не в `deliver` — не сбрасывается), 4 (обе линии kimi) и
  deepseek 4 (`_ANCHORED` теперь только в главной нити, рабочие его не
  читают).
- `anchor_fresh` ставит `cursor` и `origin` на реплику Автора;
  `session_fresh` — только не-error и не голосу без сессии (субагент 3).
- `anchor_targets` — после `_cap_group`, при `--once --prefer` —
  `[prefer]` (субагент 2); заметка о монологе — после реплики Автора
  (субагент 7).
- `resolve(project=)`: событие/запись другого проекта — отказ; записи
  без поля — общие, как у `read_events` (субагент 5); комната, дирижёр и
  окно передают проект события.
- `run`: rc=2 у pick — «кривые аргументы (якорь или --exclude)», не
  «маяк» (субагент 6).
- Поле `anchor` у ответа голоса — тот же словарь, что у реплики Автора
  (deepseek 3); `_find_live` — полный разбор, если подстрока не нашла
  (deepseek 2), тест с иным порядком ключей.
- Тесты: +7 проверок (состояние на диске, обе линии kimi, порядок
  заметки, чужой проект, origin, полный разбор).

Не дефекты (проверено): `read_events(since=N)` отдаёт `id > N`, значит
`since = id − 1` даёт ровно реплику Автора (deepseek 5); `pick_voices`
читает автора и текст, id не использует (deepseek 6); `chain_mono`
пропускает ответы голосов НАМЕРЕННО — цепочка и есть «Автор → X →
Автор → X», разрыв — только реплика Автора без якоря или к другому
адресату (deepseek 1; порог назван догадкой в своде, это сигнал, не
запрет).

Долги (названы): ревизия grok не состоялась (три попытки, ни одного
вердикта) — при живом канале пройти якорь его глазами; баланс kimi;
`codex exec resume` со stdin по-прежнему не проверен (лимит); толщина
ребра «follows» для доски; версии правок (`continues`) якорь не
различает.
