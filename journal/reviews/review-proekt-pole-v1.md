## Ответы дословно


=================== codex
1. **live.py, `next_id(): ev = read_events()` — подтверждённый критический дефект:** нумерация зависит от проекта, возникают повторные ID; фикс: вычислять `max(id, default=0)+1` по `read_events(all_projects=True)` внутри общей блокировки записи.

Новый проект без событий получает ID=1 даже при заполненной общей ленте. Блокировки сериализуют запись, но ошибку выбора ID не исправляют. Курсоры `since` и SSE `Last-Event-ID` могут пропускать события, особенно в окне без проекта, которому видны все проекты. Уже возникшие дубли требуют отдельного восстановления журнала и сброса клиентских курсоров: исправление генератора устраняет только будущие коллизии.

2. **roundtable.py, `stop_window(): _is_window_pid(pid); os.kill(pid, SIGTERM)` — гонка проверки и использования PID:** между операциями процесс может завершиться, а PID достаться другому процессу; фикс: открыть `pidfd`, проверить соответствующий процесс и сигналить через этот дескриптор.

**Предположение:** если `_is_window_pid()` проверяет только UID и наличие `roundtable.py` в командной строке, посторонний процесс может пройти проверку. Реализации здесь нет. Карточке также нужна идентичность запуска, например PID вместе со `starttime`: иначе после переиспользования PID она способна показывать старые проект и порт. Отсутствие `finally` при SIGKILL само по себе нормально: уборка мёртвых карточек в представленном коде предусмотрена.

3. **roundtable.py, `/acts: if len(order) >= 300: break` — подтверждённая потеря метаданных:** обход заканчивается сразу после обнаружения 300-го акта, оставляя более старые `accepted` и `edit` непрочитанными; фикс: ограничивать добавление новых актов, продолжая сбор данных для выбранных.

Это касается и ранее найденных актов, если их стартовые события лежат глубже. Возможны неверное время старта, пустая подпись и отсутствие `edit`, необходимого для группировки ревизий.

4. **roundtable.py, SSE `f.readlines()` и `_line_in_project()` — подтверждённая линейная стоимость подключения:** весь журнал читается и разбирается до выделения последних 80 событий проекта; фикс: индекс проекта и ID со смещениями либо общий кэш чтения. Тысяча событий сама по себе ещё не доказывает проблему производительности; существенны размер строк, рост журнала и частота переподключений.

`belongs()` сравнивает пути на точное равенство: окно `Film/` внутри песочницы старых событий без проекта **не увидит**; увидит события с собственным `project`. Окно с `PROJECT=None` видит всё. Это соответствует приведённому правилу, не наследованию по каталогам.

Все 14 вызовов по выдержкам проверить нельзя. Глобальный просмотр обязателен для генератора ID и операций, обслуживающих все проекты; интерфейсные выборки должны сохранять фильтрацию. JS отсутствует: группировку, сброс `isRev` и XSS оценить невозможно.

В smoke отсутствие `room.jsonl` допускается условным копированием; обязательность файла и порядок определения `RT_DIR` не показаны. `SMOKE_LIVE` по умолчанию равен **1**: запуск без явного нуля остаётся платным, если вызов управляется этим флагом.
