# Ревизия: память нити из ленты для голоса без сессии (2026-09-22)

Повод: вопрос Автора «продолжая разговор в папке проекта, все
предыдущие разговоры у каждого CLI и HTTP-клиента в памяти — или как
сейчас?». Ответ: у пяти голосов память держит CLI (resume / -c /
session), у deepseek-http сессий нет — он один не помнил разговор.
Решение Автора: оставить HTTP и собирать контекст из ленты самим, по
галочке рядом с моделью, умолчание — включено.

Сделано:
- `chamber/live.py`: `no_session` у deepseek; `memory_on(name)`
  (`CHOIR_<ГОЛОС>_MEMORY`, умолчание вкл.); `MEMORY_CAP`
  (`CHOIR_MEMORY_CAP`, 60000 симв.); `build_prompt(memory=True, origin)`
  — устав и цель каждый ход, «ИСТОРИЯ ЭТОЙ НИТИ» с рождения нити вместо
  дельты, свои реплики как «Вы», смены цели кроме действующей (она в
  шапке), потолок режет старейшие целиком и называет обрезку — и когда
  срезано всё; обрезка по origin названа («нить ведётся с события №N»);
  `_origin_of(st)` — одна функция для промпта и состояния: origin из
  состояния, иначе курсор, ноль → хвост COLD_TAIL, не архив; `deliver`
  — origin сохраняется в состояние до сдвига курсора; событие реплики
  несёт `memory: "feed"`.
- `roundtable.py`: `MEMORY_VOICES` из `live.VOICES`; `POST /voices
  {memory}` — только room, только голос без сессии, отдельным
  запросом; хранится в room-паре `rt-voices.json` (белый список +
  валидация); `GET /voices` → `tab.room.memory/can_memory/memory_cap`;
  `_spawn_env` → `CHOIR_DEEPSEEK_MEMORY=0/1`; галочка «память» в строке
  голоса на 💬 с откатом при ошибке.
- `test/memory_test.py` (17), `voices_http_test.sh` +8, `chamber/CLAUDE.md`
  — раздел. Живьём: две реплики deepseek на копии журнала — второй ход
  вспомнил кодовое слово («ЛАМПА»), события с `memory: feed`.

Формат: мини-ревизия read-only (codex, grok, kimi, deepseek, gemini-http;
субагент построчно с прогоном тестов).

## Записи

**codex — отказ канала.** Дважды rc=1: «The 'gpt-6-astra' model is not
supported when using Codex with a ChatGPT account» — в
`~/.codex/config.toml` (изменён 2026-09-22 17:08) модель gpt-6-astra; с
явной `-m gpt-5.6-sol` — тот же отказ. Мнения нет; факт — Автору.

**kimi — ОДОБРЯЮ.** «Потолок: если срезаны ВСЕ события, блок не
рендерится и cut_note теряется — голос не узнает, что история была.
Дубль цели: goal-события в историю всегда, а актуальная цель в шапке.
У fetch в onchange нет таймаута. Слабая проверка в тесте через or.
Наблюдения: setdefault(origin) всем голосам — при позднем включении
памяти первая подача потянет со старого origin, cap защищает; потолок
считает только text+40; _spawn_env и валидация обобщены по
MEMORY_VOICES.»

**deepseek — ОДОБРЯЮ.** «origin берётся из cursor; при cold start 0 нить
импортирует всю ленту. Если потолок срезал всю историю — обрезка не
названа. goal дублируется с шапкой. _spawn_env ставит флаг без учёта
scope. В title зашито 60000. Свои pass/error помечаются «Вы» как
реплики. Тест через or не проверяет заявленное.»

**gemini — отказ канала** (503 «high demand» по всем пяти ключам).

**grok — ОТКАЗ.** «Ноль как origin не закрепляется: `or 0` и пересчёт
хвоста при нуле — после первого хода на короткой ленте в файле
`origin: 0`, а промпт каждый ход сдвигает рождение к last_id−COLD_TAIL;
комната короче 40 событий должна помниться целиком и теряет начало,
строка «с события №N» расходится с файлом. Потолок считает не то, что
печатается: error идёт как detail[:80], а size берёт text — длинный
stdout ошибки вытесняет реплики. Снятие цели выпадает из истории:
goal="" совпадает с пустой текущей и отбрасывается — отменённая цель
выглядит действующей. Галочка: disabled снимает фокус, сторож
activeElement отпускает узел, опрос /voices пересобирает галочку из
старого t.memory; change всплывает в делегат #voices, и в PICK_OFF
садится "on". memory_test зовёт deliver двоих — beacon() в сеть. Не
дефекты: слепой ход читает ленту до публикации; context_sha от этого
промпта; _spawn_env получает весь ростер; свои pass/error как «Вы».»

**Субагент (построчно, пробники) — ОДОБРЯЮ.** «Цена у нити без проекта:
cold start cursor=0 → origin=0 → история с id 1 каждый ход до потолка —
для дельты этот случай огорожен COLD_TAIL, память его возвращает.
Заголовок обещает больше, чем даёт старой нити: обрезка по origin не

проверка origin тривиальна (стаб не пишет состояние). Потолок считает

зашито. Подтверждено: setdefault(origin) до cursor=top; blind — в
историю попадает только опубликованное; «Вы» для своих pass/error;
context_sha от реального промпта; порядок импортов MEMORY_VOICES;
_spawn_env получает все голоса → быстрый вопрос и handoff покрыты; JS
откат и activeElement-guard; валидация файла. memory 11/11; http —
секция memory 7/7, пять FAIL в /access от чужого живого bwrap на машине
(ревизия grok шла параллельно) — к дифу не относятся.»

## Что сделано

- `_origin_of`: ноль → хвост COLD_TAIL, одна функция для промпта и
  состояния (субагент, deepseek); обрезка по origin названа (субагент).
- Обрезка названа и при полностью срезанной истории (kimi, deepseek);
  размер события — text или detail или goal (субагент).
- Действующая цель — только в шапке, в истории — прошлые смены (kimi,
  deepseek, субагент).
- Потолок в подсказке — из сервера (`memory_cap`), не число (deepseek,
  субагент).
- Тест: проверка второго хода без «or», новая нить при длинной ленте
  (origin > 0, «шум 0» не показан), полностью срезанная история, смена
  цели (kimi, deepseek, субагент).

- `_origin_of`: записанный ноль — «с начала», не пересчёт; хвост только
  у нити без origin и без курсора (grok).
- Размер error в потолке — как печатается (80), не stdout (grok).
- Снятие цели (пустая) остаётся в истории (grok).
- Галочка: stopPropagation (не в делегат набора вкладки), без disabled,
  сторож перерисовки по `data-busy`, t.memory обновляется (grok).
- Тесты: снятая цель, `_origin_of` с записанным нулём; memory 17/17,
  http 111/111 (пять FAIL прошлого прогона — чужой bwrap ревизии grok,
  без него чисто), autoreview 152, smoke 16.

Не сделано, названо: memory_test зовёт deliver двух голосов — жребий
публикации идёт в drand (сеть; офлайн — порядок прихода с заметкой, тест
проходит) (grok, субагент); таймаут у fetch галочки — как у остальных кнопок
окна (kimi); свои pass/error как «Вы: (промолчал)/(выпал)» — это и есть
род события в скобках (deepseek); _spawn_env общий для областей —
переменную читает только комната (`memory_on` в live.py), раунды её не
знают (deepseek).
