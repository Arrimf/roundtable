# Ревизия: стенограмма акта — вкладки как терминал (2026-09-14)

Повод: Автор — «давай плотно займёмся выводом сырого потока в быстрый
ответ. его сейчас там нет», «дирижёр отдаёт только сухую статистику»,
«хочется похожесть на общение с тобой в терминале».

Диагноз: сырой лог писался только быстрому вопросу (RT_RAW=1) и содержал
голый stdout CLI — без вопроса, шапки и итога; акт 2dc81ba2, который
смотрел Автор, старше самого механизма (03.09 против 06.09), а
единственный его быстрый вопрос после (09.09) упал на Гроке без сессии.
Дирижёр в лог получал одни заметки: вывод голосов туда не шёл вовсе.

Сделано: `chamber/transcript.py` — одна стенограмма на акт
(`<акт>.raw.log`): «❯ вопрос», «→ голос · нить · мысли» + «$ argv»
(промпт заменён меткой), поток stdout+stderr CLI/адаптера по мере
прихода, «● голос N с M симв.», строки дирижёра. live.py (комната,
быстрый вопрос) и choir.py (раунды) пишут её; слепой ход копится в
памяти и ложится по закрытии в порядке публикации (правило 8.5).
Окно читает стенограмму во вкладках «дирижёр» и «быстрый ответ», рисует
события codex --json (reasoning/agent_message/command_execution).
Адаптеры deepseek-http и gemini-http переведены на потоковую отдачу:
мысли в stderr между маркерами 💭, текст в stdout по мере прихода
(DeepSeek: первый байт через 1.4 с вместо ответа через 17 с).

Формат: мини-ревизия read-only по дифу (codex, deepseek, grok) плюс
построчная ревизия субагентом Claude на живых файлах. Проверка вживую:
изолированное окно 8796, быстрый вопрос deepseek (стенограмма с
мыслями), ход комнаты, скриншоты вкладок.

**Расход, о котором надо сказать (правило 4):** для проверки вкладки
«дирижёр» я послал в тестовое окно обычную реплику в комнату (не
`--once`); `--voices` ограничивает только первый ход, дальше разговор
пошёл по всему составу: deepseek 66 с, claude 26 с, codex 26 с, grok
75 с, claude 34 с, вступал kimi — прервано через `/abort` на 4-й

как правило для тестов.

## Ответы дословно

### codex (rc=0)

Вывод: ошибки есть; гарантия «ни байта ответа на диске до закрытия» не выполняется.

- **P1 — слепота обходится через прежние пути записи.** В [live.py](~/AiSandbox/RoundTable/chamber/live.py:1348) Codex получает обычный `answer.txt`. [DeepSeek](~/.local/bin/deepseek-http:258) сохраняет ответ в историю, [Gemini](~/.local/bin/gemini-http:459) — в сессию/историю сразу после своего завершения, пока другие голоса ещё работают. `HOLD_TR`/`BLIND_TR` этого не предотвращают. Это существовавшие обходы, оставшиеся после изменения.

- **P1 — усечённый SSE принимается за успех.** Оба парсера допускают EOF без подтверждения завершения; Gemini дополнительно подставляет `finishReason="STOP"`. Подмена потока подтвердила: единственный чанк `partial` без завершающего события возвращается как ответ, Gemini — с кодом 200. Ошибочные JSON-чанки молча пропускаются.

- **P2 — DeepSeek теряет повторы до первого байта.** `_partial_out()` для pipe всегда возвращает `True`. Поэтому даже ошибка соединения до вывода прекращает попытки. Воспроизведено с пустым pipe.

- **P2 — целостность строк нарушается в choir.** `_pump()` передаёт последний фрагмент без добавления `\n`: воспроизведено `tail` + `err\n` → `tailerr\n`. Оба сборщика также задерживают текст без переводов строки; первый байт адаптера ещё не означает первый байт во вкладке.

- **P2 — завершение читателей не гарантировано.** `run_watched()` после ограниченного `join()` возвращает результат даже при живых читателях. `BLIND_TR.clear()` оставляет им ссылки на списки; поздние байты могут потеряться при выгрузке. Атомарность `append` не обеспечивает завершённость буфера.

- **P2 — дедлайн Gemini не абсолютный:** остаток передан socket timeout, но внутри чтения прошедшее время не проверяется.

Смена `act→raw` сбрасывает смещение; старые акты имеют fallback. Однако счётчик `live.deliver()` печатается только в act и после переключения исчезает.

Текущие argv Kimi/Claude/Codex передают промпт отдельным аргументом; маскирование срабатывает. Пути остаются. Очистка секретов выполняется при выдаче, не записи; безусловную утечку ключа через HTTPError не подтвердил.

`expand` буферизуется; живой `catchup` использует `"open"`. Последовательные ходы сбрасывают HOLD. Причина Gemini `"stream"` останавливает каскад корректно.

Тестам недостаёт перечисленных аварийных сценариев и проверки всех файлов во время слепой фазы. Файлы не менял.

### deepseek (rc=0)

МИНИ-РЕВИЗИЯ

Нарушений правила 8.5 в штатном blind-ходе не нашёл: шапка/поток копятся в HOLD_TR/BLIND_TR, заметки в HOLD_NOTES/BLIND_NOTES, flush — после закрытия фазы. Запись в файл защищена `transcript.write` под `threading.Lock`; `HOLD_TR/BLIND_TR` — `setdefault` под замком, `list.append` атомарен.

Ошибки/риски:

1. **deepseek-http: ложное «уже печатали» на pipe.** `_partial_out()` для pipe всегда True: `sys.stdout.tell()` даёт OSError. В комнате stdout CLI — pipe, поэтому любой `URLError`/`TimeoutError` до первого байта отключает ретраи, хотя вывода ещё не было. Нужно фиксировать факт начала вывода внутри `stream_read`, а не по `tell()`.

2. **choir._pump: последняя строка без `\n`.** `tee` пишет строку как есть; на EOF без перевода строка может склеиться со следующей строкой стенограммы (`_out` не добавляет ведущий `\n`). Стоит гарантировать завершающий перевод.

3. **Таймауты urlopen — не общий дедлайн.** В `deepseek-http`/`gemini-http` `timeout=...` задаёт таймаут одного чтения, а не всего стрима: «капающий» ответ может жить дольше. В choir/live прикрыт hard_limit, но прямой вызов — нет.

4. **`head()` маскирует промпт только при точном равенстве строки.** Если команда передаёт промпт через `--prompt-file` или с лишним `\n`, метки не будет. Проверить, что в argv не попадает сам текст.

5. **gemini-http: обрыв после thoughts, но до текста** не бросает `StreamBroken`: stdout не дублируется, но stderr/транскрипт при ретрае задвоится.

Тесты не покрывают: переключение источника act→raw в окне, обрыв потока после частичного вывода адаптеров, JSON-рендер codex, повторные ходы одного голоса в одном акте.


### grok (rc=0)

Читаю полный запрос и живые файлы — ищу, не ложится ли чужой ответ на диск до закрытия слепой фазы.Диф обрезан — читаю живые файлы вокруг слепой фазы, адаптеров и окна.Сверяю сборку argv, `_run_capture` и закрытие слепой фазы — там чаще всего утекает промпт или чужой ответ.**Слепой поток на диск до закрытия не ложится; главный дефект — `deepseek-http`: в pipe `_partial_out()` всегда True, ретраи сети до первого байта сняты.**

**(а) 8.5.** Шапка и stdout+stderr слепого хода копятся в `HOLD_TR`/`BLIND_TR`; `_note`/`_say` — тоже. `cmd_expand` делает flush сразу (один голос); `catchup` идёт как `open`. На диск во время фазы попадают только строки дирижёра: вопрос, заголовки и у choir «· готово N/M». В live тот же счётчик — `print` в лог акта, не в стенограмму. Дети наследуют `RT_ACT_DIR`/`RT_ACT_ID` и могут открыть файл; чужих ответов там нет.

**(б)** live: `_put` под замком, целые строки. choir: два `_pump` в один `tee` — строки целые (`write` под `_LOCK`, `append` под GIL), stdout и stderr чередуются. Открытый `deliver` нескольких голосов пишет в один файл сразу — потоки смешиваются (слепой flush — по голосам). `dict(BLIND_TR)` копирует словарь, не списки; после `join(5)` живой pump может дописать в уже выложенный или потерянный буфер. Два хода одного имени в одном слепом пакете делили бы буфер (в `deliver` так не бывает).

**(в)** `head` меняет только `x == ptext`: срабатывает у claude/codex (последний аргумент) и kimi `-p`. grok/gemini/deepseek показывают `--prompt-file PATH`, не текст. Ключ в URL gemini: `str(HTTPError/URLError)` обычно без URL.

**(г)** На pipe любое исключение в `call()` (таймаут, обрыв до байта) → код 1 без повтора; `HTTPError` ретраится. Gemini `return 1,"stream"` не в списке каскада (`gateway|quota|nomodel|empty`) — запасная модель не зовётся (иначе stdout склеится). HTTPError до тела — ротация жива. `timeout` urllib — на каждый read, не на весь поток. Хвостовой `print()` даёт лишний `\n`.

**(д)** Нет `.raw.log` → лог акта; смена act→raw сбрасывает хвост. Старые акты без файла остаются на act. Вкладка «дирижёр» комнаты во время слепого хода не видит «· готово»: источник уже raw.

**(е)** Нет: `deliver`/`_run_phase` e2e, pipe-ретрай, гонка двух голосов, logKind, SSE/каскад, `head` с `--prompt-file`.

## Что сделано по находкам

- **Повторы deepseek на pipe** (codex, deepseek, grok, субагент) — флаг
  `_PRINTED` ставит сам `stream_read` при первой печати; `tell()` убран.
- **EOF без завершения = успех** (codex P1, субагент 4) — deepseek:
  `done` по `[DONE]`/`finish_reason`, иначе `StreamBroken`; gemini: без
  `finishReason` — `StreamBroken` после вывода (без повтора) или `OSError`
  до вывода (повтор/ротация ключей); подстановка STOP убрана.
- **Незакрытый маркер мыслей** (субагент 3, deepseek 5) — закрывающий
  маркер в `finally` у обоих адаптеров; gemini считает выводом и мысли.
- **Дедлайн потока** (субагент 8, codex, deepseek) — проверка дедлайна
  внутри цикла чтения у обоих адаптеров.
- **Перемешанные потоки в открытой фазе** (субагент 2, grok) — live и
  choir: при нескольких голосах поток копится до конца голоса и
  выкладывается перед его итоговой строкой; один голос (быстрый вопрос,
  передача слова) идёт в файл по мере прихода.
- **Хвост без `\n` в choir._pump** (субагент 6, codex, deepseek) — tee
  дописывает перевод строки.
- **Счётчик слепого хода и «маяк недоступен»** (субагент 5, codex, grok)
  — в стенограмму.
- **Застревание буферов** (субагент 9) — live: сброс в `except`; choir:
  `BLIND_TR.clear()` в начале фазы, `HOLD_OPEN` в `finally`.
- **Эвристика рендера** (субагент 7) — шапка только по «→ голос · », «$»
  только сразу после шапки, ❯ не внутри потока голоса; итоговая строка
  «● голос N с» закрывает поток.
- **Codex P1 «слепота обходится через прежние пути записи»**
  (answer.txt Кодекса в комнате, история deepseek/gemini на диске) —
  верно и существовало до этой правки; в choir.py ответ Кодекса идёт
  через fifo, в комнате (live.py) — обычным файлом. Не чинилось здесь:
  записано долгом ниже.
- **Незавершённые читатели run_watched после kill** (codex P2, grok) —
  не менялось: касается только снятых по таймауту голосов; поздние
  байты уходят в уже выложенный список в памяти, не на диск.
- **head() только при точном равенстве** (deepseek 4) — проверено по
  всем VOICES обоих модулей: промпт всегда отдельный элемент argv или
  файл; покрыто тестом.
