# Свод раунда: Choir поверх Orca или свой транспорт?

*Клод (Fable), 2026-08-14. Затравка — `ВОПРОС-АРХИТЕКТУРЫ.md`.
Ответили все четверо: Codex (MCP), Грок (pty, read-only), **Кими
(первый раунд полноправным участником)**, Джемини (через новый
враппер с ротацией ключей — канал больше не «приходящий»).
Дословные ответы: `ОТВЕТ-*-АРХИТЕКТУРА.md`.*

## Сначала расхождения — как велит протокол

### Главное: как дать Автору «общий чат внутри Orca» — четыре разных ответа

| Кто | Способ | Аргумент |
|---|---|---|
| **Грок** | **Плагин-панель** (не форк!) | Раскопал исходники: `examples/plugins/hello-orca`, `contributes.panels` + `panel.html`, capability-gated (`workspace:read`, `terminal:send`, `notifications:show`, `events:subscribe`). Панель = **вид** ленты, движок снаружи. «Пожелание Автора — про то, куда смотреть, а не про то, кто владеет лентой» |
| **Кими** | **Своя веб-лента** (SSE поверх `room.jsonl`) | «Тот же общий чат рядом с терминалами, только терминалы орковские, а лента наша и версионируется». Форк = «нанимаемся сопровождать чужой desktop-клиент» |
| **Кодекс** | Форк с панелью — **позже**, «вероятно, конечная форма» | Но только после доказательства API и стабилизации контракта; форк обязан лишь отображать, не хранить единственную копию истории |
| **Джемини** | Про панель промолчал; форк — «смерть на быстром апстриме» | «45k звёзд + daily ships похоронят под мерж-конфликтами» |

Против форка **трое из четырёх**. Находка Грока (плагинный API у Orca
уже есть) закрывает пожелание Автора дешевле всех — если плагин
переживает апдейты.

### Второе расхождение: считать ли Orca транспортом вообще

- **Грок жёстче всех:** Orca **не транспорт**. Публичный CLI — это
  `worktree create/snapshot/click/fill`, плагин умеет `terminal.sendText`
  и слушает `agent.status.changed` — «это автоматизация UI, не
  протокол реплик». Строить Choir на эмуляции клавиатуры нельзя.
- **Кодекс мягче:** Orca — сменный runtime за адаптером, но «не
  доказан программный двусторонний API; если API — только UI-клики,
  это не транспорт».
- **Кими и Джемини:** Orca — второй адаптер, подключаем ПОСЛЕ MVP на
  прямых вызовах.

### Третье: моё предложение признано наполовину неверным

Формулировку затравки «Choir становится тонким слоем поверх Orca»
**отвергли трое**. Кими сформулировал разворот: «Правильнее наоборот —
**Choir автономен, Orca один из транспортов, и не первый**». Грок
объяснил почему: примитив Orca — **изоляция** (свой worktree, своё
состояние), примитив Choir — **общая лента**; это не два слоя одной
задачи, а противоположные инварианты. Если каждый голос в своём
worktree, журнал либо размножается на N копий, либо Choir снова пишет
за всех — **откат к поколению 1, где Клод был единственной шиной**.

## Единогласно (4/4)

1. **Ядро комнаты — наше.** `room.jsonl` остаётся первоисточником;
   Orca никогда не владеет разговором.
2. **Сначала MVP на прямых вызовах CLI** — они и есть эталонный
   транспорт (сессии у всех CLI уже есть: `codex exec resume`,
   `grok -c`, `kimi -c`).
3. **Интерфейс драйвера голоса** с двумя реализациями: `direct-cli`
   (эталон, всегда рабочий) и `orca` (опция). Джемини дал сигнатуру,
   Кими — три операции (`send(delta)`, `status()`, `reset()`), Кодекс —
   контракт события (`voice`, `backend`, `session_id`, номер последней
   обработанной записи).
4. **Fallback-контракт:** версия Orca пинится, автообновление
   выключено; адаптер сломался → в ленту `error` + переключение голоса
   на `direct-cli`; `choir tail` и чтение журнала работают без Orca.
   Кими добавил критерий выхода: **два подряд релиза, ломающих
   адаптер — транспорт закрываем**.
5. **PR в апстрим — не план, а подарок.** Общий чат противоречит их
   философии изоляции; темп стола от чужого ревью не завязывать.

## Что проверить на установке (объединённый список, по убыванию силы)

1. **Есть ли структурированный I/O агента** — «отправить реплику →
   получить текст ответа» программно (HTTP/CLI/событие), а не
   `click`/`fill`/`terminal.sendText`. **Стоп-кран:** нет — Orca
   остаётся средой человека, транспорт закрыт (все четверо).
2. **Сессия адресуется извне** (id, а не вкладка UI) и переживает
   рестарт Orca; контекст не пересоздаётся заново (Кодекс, Джемини).
3. **Worktree vs журнал:** запустить трёх агентов на одном вопросе —
   `room.jsonl` это одна inode или три копии? Кто коммитит? (Грок —
   специфичная и важная проверка).
4. **Права:** можно ли выдать голосу read-only + запись только в один
   каталог (наш `board-write`), выживает ли Landlock Грока без
   `/dev/tty` внутри Orca (Грок, Кими, Джемини).
5. **Кими с `concurrency=1`:** очередь или веер и 429 (все).
6. **Стабильность:** один и тот же раунд на двух соседних релизах;
   плагин `hello-orca` как канарейка UI — переживает ли апдейт (Грок).
7. **Телеметрия:** что уходит наружу — журнал стола не должен утекать
   «анонимной статистикой» (Грок, единственный, кто вспомнил).

## Что теряем, если отдать комнату Orca (сводно)

Доказательность. Конкретно: журнал перестаёт быть первоисточником
(часть правды — кто ответил, кто упал по таймауту — переезжает во
внутренний формат сессий); честный `error` подменяется чужим статусом
UI; семантика `ask`/`pass`/`verdict`/`join`/`leave` исчезает; дирижёра
нет вовсе; статистика перекоса недоступна; read-only рецензентов
подменяется изоляцией worktree (это защита агентов друг от друга, не
политика прав); теряется переносимость разговора между транспортами.

## Решение к утверждению Автором

1. Строим **Choir-ядро** (лента + дирижёр + драйверы) на прямых
   вызовах CLI — как и планировалось в MVP.
2. Orca **ставим и проверяем** по списку выше (Автору нужен sudo:
   `pamac install orca-ide-bin`); она в любом случае полезна как
   среда человека и, возможно, как второй драйвер.
3. Пожелание «общий чат в интерфейсе Orca» закрываем **плагином-
   панелью** (путь Грока) — если проверка №6 покажет, что плагины
   переживают апдейты. Запасной вариант — своя веб-лента (путь Кими),
   она нужна и сама по себе (этап «Хор»).
4. Форк Orca — **нет** (3 из 4 против).
