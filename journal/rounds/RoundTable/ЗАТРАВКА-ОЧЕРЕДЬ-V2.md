# Затравка `очередь-v2`: ревизия исправлений после круга `ферма-gui`

В круге `ферма-gui` стол нашёл в очереди счётного узла три живых бага
и перевернул дизайн. Пункт 1 плана — очередь — переписан. Прошу
**короткую** ревизию: код и факты проверки ниже, вердикт первой строкой.

## Файлы
- `ops/calc_node/files/runq.py` — очередь v2 (один код на все узлы;
  env `CALC_DIR/CALC_PY/CALC_PAR`)
- `ops/calc_node/deploy_code.sh` — деплой кода по sha с рабочей машины
- `ops/calc_node/README.md`, раздел «Очередь v2» — таблица было/стало

## Что закрыто (каждое — проверено на живой ноде)
1. Коллизия логов → имя `<номер>_<sha8 строки>`.
2. Глоб во флаге → argv списком через subprocess, валидатор отклоняет
   `;&|$\`<>*?()"'`. Проверка: `research.evil --flag $(rm -rf /)` и
   `research.evil *.py` → ОТКЛОНЕНО без запуска.
3. «done = взято» → `taken` + `done` (с кодом); после рестарта при трёх
   бегущих задачах все три вернулись (`ВОССТАНОВЛЕНИЕ: 3 задач`).
4. Drain → файл `PAUSE` (новые не берутся, текущие дотикают) — проверено.
5. Cancel → `setsid` + `killpg` TERM→KILL через 20 с; сирот 0.
6. Код по sha → `~/calc/code/<sha>/`, строка `sha=… research.…`;
   `sha=deadbeef` → ОТКЛОНЕНО (нет кода).
7. `state.json` атомарно раз в 5 с — это контракт для агента/GUI.

## Известное ограничение
14 research-модулей делают `sys.path.insert(0, "~/Cursor_W")` ради
`broker_connector.data.bank`; sha-снимок ссылается на живой
`broker_connector` симлинком. Для данных — правильно (банк общий); если
там появится исследовательский код — снимок не зафиксирует.
