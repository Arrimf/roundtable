# Свод «право-записи-v1»

**Единогласно: первой — А (лоток), но исходную А не принял никто: «риск нулевой» опровергнут, стол выставил предусловия — песочница, прибитая к cwd лотка; закрытые от перезаписи журналы; раздельные записи «предложил»/«принял». Б-как-worktree отвергнута всеми: общий `.git` и тот же uid делают «файловую гарантию» фикцией; честная Б — полный клон + отдельный uid/контейнер. В — не механика: профили песочницы есть лишь у Грока и Кодекса (уточнение kimi к затравке), отзыва «пера» нет ни у кого.**

## Расхождения

| Спор | Позиции |
|---|---|
| Хватает ли лотка | deepseek: без стоп-механики (аренда / diff-контракт / надзиратель) А — это В с другим путём · grok: аренда «полуслова» не остановит · claude: отзыв под тем же uid — не механика, механичен только профиль, зашитый на старте процесса |
| Ревизия при шести писателях | kimi + grok: перенос каждый раз руками Автора (в README так намеренно) · deepseek: это сериализация, узкое место — нужен подписанный батч · claude: субагент на каждый патч, стол — только на код дирижёра и канон |
| Чем чинить append-only | grok: `chattr +a` → сам снял (без root — EPERM; codex: `+a` не мешает поддельному дописыванию; claude: ломает git) → отдельный писатель журналов |

## Кто менял мнение

- **deepseek** — единственная смена выбора: Б+ → А, приняв довод codex про общий `.git`.
- **claude** — принял: перенос из лотка делает Автор, не дирижёр (ошибку затравки нашёл kimi); «перо» частично механизируемо.
- **grok** — снял собственное условие `+a`, проверив: `CapEff` пуст.
- **kimi** — сузил «цена ошибки — одна папка» до «только при реальной песочнице» (у Кими её нет).
- **codex** — выбора не менял.

## Принято единогласно

- `room.jsonl`/`live.jsonl` — `644`, переписываемы тем же uid: append-only сегодня обещание; закрыть до выдачи записи (нашёл grok, перепроверили kimi и claude).
- На слепой фазе записи нет ни у кого — боковой канал (claude).
- В журнале два события с разными авторами и sha: «голос предложил» / «стол принял»; расхождение sha ловит молчаливую правку шлюзом (все пятеро, формулировки разные).
- Для HTTP-голосов единственный уравнитель — патч текстом в ленту (четверо).
- review-gate верит `--by` на слово и живёт только в хуке Клода: перенос из лотка обходит единственный механический гейт (kimi); `.git/hooks` пусты (grok).

## Упущенное всеми (rebut1)

- claude: у Автора все права с первого дня — и ноль карточек; право писать ≠ причина писать.
- codex: ревизию прибивать к базовому дереву, не только к sha патча.
- deepseek: проверки путей — гонка TOCTOU; стоп-крана посреди записи нет ни в А, ни в Б, ни в В.

## СВОИ ИДЕИ

- **claude**: испытание взломом границы после каждого обновления CLI; канарейки-приманки у запретных зон.
- **codex**: равноправие мерить долей предложений, дошедших до ревизии; в приёмке — тройка `base+patch+result` sha.
- **deepseek**: контракт на diff (цель + список файлов); запись как fd-токен, который сторож захлопывает снаружи.
- **grok**: журналы пишет отдельный процесс (FIFO у `choir.py`); тройка (ino, size, sha) на входе/выходе, статус `tamper`.
- **kimi**: записи не выдавать вообще — diff в лоток, `git apply --author` после ревизии; пломба-хеш в момент появления файла.

## Нерешённое

1. Стоп-механика при одном uid — надзиратель/токен не спроектированы.
2. Человек на каждом переносе или батч — решение Автора.
3. Чем именно закрыть журналы — предусловие всего, механика не выбрана.
