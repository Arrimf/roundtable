### 2. Единогласный консенсус и изменения мнений

#### Принято единогласно:
1. **Вкладка на каждого вендора с сырым `tail -f` в текущем коде невозможна:** Лог акта собирается на весь такт сразу (один файл на 6 голосов), а выводы голосов буферизуются в памяти.
2. **xterm.js / PTY / tmux вредны:** Ломают single-file архитектуру `roundtable.py`, создают оверхед, а у HTTP-голосов (DeepSeek, Gemini) терминала нет в принципе.
3. **Правило 3 (Дословность) неприкосновенно:** Логи инструментов и reasoning запрещено писать в `live.jsonl` или `room.jsonl`. Канонический финал берется только из итогового ответа.
4. **Состояние HTTP-адаптеров:** `deepseek-http` шлет `"stream": false` и игнорирует `reasoning_content`; `gemini-http` вызывает нестриминговый метод и отбрасывает блоки `thought`.
5. **Модель угроз слепоты:** Агентные CLI (`claude`, `codex`, `grok`, `kimi`) уже пишут свои сессии во время слепой фазы в `~/.claude`, `~/.codex` и т.д. под тем же UID. Однако трансляция мыслей в UI во время слепой фазы создает **новую утечку через Автора**, который пишет следующий промпт.

#### Кто изменил мнение во 2-й фазе:
* **kimi & gemini:** Отказались от идеи «быстрого MVP на фронтенде за 100 строк», признав доказанный замер: файлы `rt-acts` содержат 0–159 байт до завершения акта из-за отсутствия `flush`/`-u`.
* **claude:** Уточнил модель угроз: проверил доступность локального порта окна из песочницы CLI и подтвердил, что любая трансляция слепых мыслей в UI доступна агентам по HTTP через `localhost`.
* **codex & deepseek:** Сместили фокус с «вывода CoT» на «трансляцию нейтрального статуса зависания/активности».

### 3. Уникальные идеи участников (`СВОЯ ИДЕЯ`)

* **claude:** *Аудит слепоты постфактум.* По завершении раунда автоматическим `grep` по локальным журналам сессий (`~/.claude`, `~/.codex`) проверять, не заглядывал ли агент в каталоги соседей во время слепой фазы.
* **codex:** *Эксперимент с Honeytoken.* Внедрять уникальный безвредный маркер в журнал одного голоса и автоматически искать его появление в ответах других участников раунда для физической проверки изоляции.
* **deepseek:** *Протокол «Нотариус».* Во время хода отдавать в UI только криптографический digest и длину запечатанного CoT-конверта, а раскрывать содержимое по клику только после завершения фазы.
* **gemini:** *Эфемерный UNIX-сокет (`choir.sock`).* Передавать телеметрию из `choir.py` в веб-сервер через сокет в памяти, минуя диск, чтобы агентные CLI не могли прочитать чужой ход через файловую систему.
* **grok:** *Счётчик каскада через Автора.* Автоматически сравнивать промпт Автора с CoT-слоем предыдущего хода на наличие лексем, отсутствовавших в финальном `text`, чтобы математически измерять нарушение правила 9.
* **kimi:** *«Нулевой транспорт».* Не плодить эндпоинты и файлы, а расширить существующее SSE-событие `act_status` полем live-хвоста (400–2000 символов) прямо в текущем протоколе.
