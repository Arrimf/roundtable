# Затравка `агент-v1`: ревизия агента узла и координатора

Пункт 2 плана фермы, построен по вашему же вердикту в круге `ферма-gui`.
Прошу **короткую** ревизию: вердикт первой строкой, дальше по номерам.

## Что построено (коммит e85eec4)

**`ops/calc_node/files/agent.py`** → `~/calc/agent.py`, служба `calc-agent`
на узле. Системный python3 + psutil (не исследовательский venv). Раз в 5 с
собирает снимок и **POST-ит** координатору:
- `cpu`: percent_per_core, percent_total, cores, loadavg, temp_c
- `mem` / `disk` / `boot_time`
- `queue`: содержимое `state.json` очереди v2.1 как есть
- для каждой бегущей задачи — `log_tail`: последние 3 строки её лога
  (хвост читается seek'ом с конца, не весь файл), обрезка 220 симв.
- `send_failures` — счётчик неудачных отправок

Агент **не слушает порт, не принимает команд, ничего не выполняет**.
Управление очередью (enqueue/cancel/PAUSE/PAR) — запись файлов в `~/calc`
по ssh, тем же каналом, которым узел админится.

Телеметрия **не буферизуется**: координатор недоступен → снимок теряется
(он мгновенный; пятиминутной давности врёт про «сейчас»). Копится только
`send_failures`.

**`ops/calc_node/files/coordinator.py`** → `~/bin/calc_alert_receiver.py`
(бывший приёмник тревог sshguard, тот же процесс и порт 8765):
- `POST /alert` — как было (тревоги, ACK только по факту показа)
- `POST /node` — снимок; токен + подсеть; атомарная запись
  `~/.local/state/calc_nodes/<node>.json` (имя файла санитизируется)
- `GET /nodes` — всё для GUI, **только с 127.0.0.1, без токена**
  (сервис работает от того же пользователя, что и GUI)
- узел старше `NODE_STALE_SEC=30` помечается `online: false`

Проверено под нагрузкой: две задачи, полоски по 8 потокам, 70 °C, хвост
`lag -20д N=146 s=-0.0340` в снимке. `GET /nodes` отдаёт валидный JSON.

## Вопросы

1. **Что здесь сломано или обещано, но механикой не обеспечено?**
   Особенно: гонка чтения `state.json` (очередь пишет через `os.replace`,
   агент читает — достаточно ли?), `log_tail` на ротации/усечении файла,
   размер снимка при PAR=16 (percpu×16 + 16 хвостов).
2. **`GET /nodes` без токена с localhost** — приемлемо, или закрыть?
   Довод за: сервис от того же пользователя, что GUI; токен в конфиге GUI
   — лишняя копия секрета. Довод против: любой локальный процесс читает
   состояние фермы.
3. **Отсутствие буферизации** — согласны? Или нужен кольцевой буфер на
   N последних снимков, чтобы GUI показывал «что было, пока сеть падала»?
4. **Чего не хватает в снимке** для вкладки «Воркеры», кроме того, что
   уже есть? Напомню боль: «сколько осталось», «на каком sha считалось»,
   «упала или доделалась» — первое и второе закрыты, третье лежит в
   `queue.counts` и `recent_done`.
5. **Своя идея** — что бы вы добавили, чего я не назвал.
