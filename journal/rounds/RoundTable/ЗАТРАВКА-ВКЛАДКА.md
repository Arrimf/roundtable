# Затравка `вкладка-v1`: ревизия блока «Узлы фермы» в GUI

Пункт 3 плана фермы (после `ферма-gui`, `очередь-v2`, `агент-v1`).
Коммит `c5b6b52`. Прошу **быструю** ревизию, вердикт первой строкой.

## Что построено

**`trading_gui_app/tabs/farm_nodes_widget.py`** — блок узлов, встроен
ВЕРХНИМ этажом во вкладку «Воркеры» (`workers_tab.py`), нижний этаж —
прежняя таблица воркеров Strategy Engine. Разделение намеренное: research
через очередь узла и trial'ы SE — разные исполнители; общей будет модель
управления, когда появится RemoteExecutor, а не таблица.

Данные — `GET http://127.0.0.1:8765/nodes` у координатора раз в 2 с, в
отдельном QThread. GUI **никуда не ходит по ssh и ничем не владеет**.

Карточка узла показывает: полоски загрузки по каждому потоку (свой
`paintEvent`, цвет по порогам 25/60%), память со свопом, температуру,
аптайм, диск; очередь тремя списками — **считается** (с временем, sha и
последней строкой лога), **ожидает**, **завершено** (✓/✗/⊘ + секунды);
хвост лога выбранной задачи в нижней панели.

Два индикатора, не один: `online` — пульс агента; живость очереди
(`runq_alive`) отдельно, иначе мёртвый дирижёр при живом агенте даёт
зелёный узел с замороженным снимком.

Поток жнётся идемпотентным `stop()`, подключённым и к `closeEvent`, и к
`aboutToQuit`: одного `closeEvent` мало — Qt шлёт его только top-level
окнам, а виджет внутри вкладки умирал с работающим QThread, и процесс
падал с abort (воспроизведено до правки, после — чисто).

Хвосты логов фильтруют предупреждения numpy и строки-разделители, иначе
«последняя строка» показывала `m2 = c2[rb] - c2[lo]` вместо
`lag -29д N=138 s=-0.0379`.

Проверено на живом узле под нагрузкой: 3 задачи, полоски по 8 потокам,
71 °C, прогресс построчно, два завершения с временем, хвост по клику.
