# RoundTable — стол, за которым сидят шесть ИИ

[English](README.md) · **Русский**

*Окно, в котором модели разных компаний обсуждают, ревьюят и правят код
вместе с человеком — как соавторы, а не как опрашиваемые по очереди
ассистенты.*

RoundTable — верстак, за которым модели разных лабораторий сидят за
одним столом с человеком: обсуждают вопросы, рецензируют ответы и код
друг друга, по очереди занимают кресло исполнителя, чтобы править
git-репозиторий, и сливают правки только через гейт ревизии. Не «человек
опрашивает ассистентов по одному» — стол.

## Голоса

| Голос | Лаборатория | Канал |
|---|---|---|
| claude | Anthropic | CLI `claude` |
| codex | OpenAI | CLI `codex` |
| grok | xAI | CLI `grok` (pty) |
| kimi | Moonshot | CLI `kimi` (последовательный шлюз: в организации одновременно один вызов) |
| deepseek | DeepSeek | прямой HTTP (`adapters/deepseek-http`); в кресле исполнителя работает `dsh` |
| gemini | Google | прямой HTTP (`adapters/gemini-http`) — только рецензент, файлов не видит |

Каждый голос сохраняет своё лицо: ответы записываются дословно, отказ
канала записывается как отказ (никогда не придумывается), журнал только
дописывается.

## Что умеет

**Живая комната** (`chamber/live.py`) — одна общая лента; каждый голос
держит свою нить и получает только дельту событий, которых ещё не видел.
Очерёдность задаёт протокол, а не самый быстрый канал: жребий публикации
на публичном маяке случайности [drand](https://drand.love) держит повестку
честной и проверяемой кем угодно.

Над лентой два переключателя: *кратко* (лимиты слов из правила 16) и
*адресно* — включаемая по желанию опция вопросов между голосами: голос
может открыть строку через `@имя`, адресат отвечает следующим, затем
добавить могут только поднявшие руку, иначе ветка закрывается и слово
возвращается человеку. Ветка помечена в журнале; ничего не уходит из
единственной ленты. Отказы каналов в комнате несут типизированный
`status` (`quota`, `auth`, `timeout`, `empty`, `error`), а цель,
поставленная целеполагателем (пока это человек), едет с каждым пакетом.

**Раунды стола** (`chamber/choir.py`) — полный протокол: жребий
commit-reveal на drand выбирает ведущего *до* того, как существует
подпись маяка (выбор нельзя подогнать под вопрос); ведущий разворачивает
вопрос в затравку; каждый голос отвечает **вслепую** (ответы держатся в
памяти дирижёра и раскрываются разом; единственному CLI, который
настаивает на записи ответа в файл, подсовывается именованный канал,
чтобы байты не легли на диск — слепота отсутствием данных, а не
обещанием не смотреть); до трёх витков возражений; свод, обязанный
назвать, где голоса *разошлись*, — расхождение здесь продукт, а не
дефект. Окно показывает каждый раунд карточкой под событием ленты:
затравка, слепой ответ каждого голоса дословно, витки и свод, с
кнопками, чтобы запустить следующий виток или свод вручную, если раунд
шёл по шагам. Раунд, запущенный из каталога проекта, несёт этот проект
каждому голосу (`--project`), а голос `claude` работает из нейтрального
каталога, чтобы видеть ровно тот пакет, что видят остальные, — а не
инструкционные файлы самого дирижёра.

**Кресло исполнителя** (`edits.py`, `executor_run.py`) — голосу можно
выдать право править репозиторий: изолированный git worktree на каждый
акт, flock-аренда, которую процесс исполнителя держит весь акт, сторож,
просыпающийся в момент падения замка, и честное различие между
«закончил» и «упал» (событие закрытия ЭТОЙ эпохи — в ленте или маркером
на диске — иначе это авария, и worktree становится уликой в карантине).

**Гейт слияния** (`merge_gate.py`) — ничто не попадает в главную ветку
без ревизии: диф уходит всем голосам, кроме исполнителя, одним
одинаковым пакетом; вердикты записываются с точным sha, который судили;
fixup автоматически сжигает старые одобрения; ≥2 одобрений и ноль
отказов открывают гейт; merge-коммит несёт трейлеры `Reviewed-by:`,
хэши базы и патча, а автором в git значится голос-исполнитель. Уехавшую
главную ветку гейт перебазирует сам — и одобрения честно сгорают снова.

## Честные границы

Всё работает под одним пользователем ОС. Замки, эпохи и печати здесь —
**обнаружение, а не предотвращение**: враждебный процесс с тем же uid
может переписать что угодно, и цель конструкции в том, чтобы он не мог
сделать это *незаметно*. Единственные настоящие песочницы уровня ОС —
те, что приносят сами CLI. Где граница тонка, докстринг говорит об этом,
а не льстит ей.

## Быстрый старт

Нужны: Python 3.11+, git и те CLI голосов, что у вас есть (`claude`,
`codex`, `grok`, `kimi`, `dsh`); для HTTP-адаптеров Gemini и DeepSeek
положите ключи туда, куда говорят README и заголовки адаптеров
(например, `~/.gemini/keys.txt`, по ключу на строку — см. `examples/`).
Голоса, которых у вас нет, просто честно падают и записываются как
отсутствующие.

```bash
mkdir -p journal && : > journal/live.jsonl   # свежая пустая лента
python3 chamber/live.py ask "привет, стол"   # первый слепой ход
python3 roundtable.py                        # окно на http://127.0.0.1:8770
bash smoke.sh                                # интеграционный смок, 16 проверок
```

Раскладка: `chamber/` — код стола (комната, дирижёр, последовательный
шлюз), `journal/` — его данные: лента, журнал раундов, нити голосов и
раунды, разложенные по проектам в `journal/rounds/<проект>/`. В публичный
репозиторий едут код, `docs/`, раунды о самом столе
(`journal/rounds/RoundTable/`) и ревизии кода (`journal/reviews/`); живая
лента и раунды других проектов остаются дома.

В окне три вкладки — 💬 комната, 🎼 раунды, 🔧 кодер — с одинаковым
наполнением: шесть голосов, у каждого своя галочка, модель и усилие
**на вкладку** (настройка комнаты никогда не протекает в раунд или в
кресло исполнителя). Умолчания явные: ячейка показывает `opus (умолчание)`
и называет, кто держит это умолчание (live.py, choir.py, собственный
конфиг CLI), а не голый прочерк. Где рычага не существует, ячейка говорит
об этом словами (у CLI kimi нет флага усилия; у `dsh` нет ручки усилия; у
gemini нет кресла). Кнопка ⟳ обновляет списки моделей из самих каналов
без единого вызова модели: Anthropic `/v1/models` через OAuth-токен CLI,
кэши CLI codex и grok, Moonshot `/v1/models` плюс алиасы CLI, `--models`
HTTP-адаптеров (`catalog.py`). Управление кодером (правка, ревизия,
слияние, adopt, лента актов) живёт в боковой панели под кнопками жребия
и показывается только на вкладке 🔧; кнопки диалога внизу не двигаются.

**Смотреть на работу, а не ждать её.** Над лентой три вкладки вывода:
🎼 *дирижёр* показывает ход оркестровки раунда вживую (кого вызвал,
очередь Кими, повторы, статусы; в слепой фазе только обезличенный
счётчик, поимённые строки выходят пачкой по закрытии фазы), 🔧
*исполнитель* — вывод CLI в кресле, ⚡ *быстрый ответ* — сырой вывод
голоса на быстрый вопрос. Вкладки опрашивают лог акта по смещению,
переживают перезагрузку страницы и вырезают ANSI, домашние пути и
строки, похожие на ключи. Галочка 💭 *мысли* (умолчание включена)
просит у каждого канала рассуждения модели там, где они есть:
thinking-блоки Claude, сводки рассуждений Codex, `reasoning_content`
DeepSeek, thought summaries Gemini — и показывает их во вкладках, с
подписью, что именно показано. Быстрый вопрос, начатый словом
`#кресло`, уходит в кресло случайному исполнителю, а не в комнату.

**Правки без ревизии не бывает.** Когда акт кресла закрывается — штатно
или с ошибкой, — окно само отправляет диф столу (всем голосам, кроме
исполнителя); если ревизия уже идёт, акт ждёт в очереди и идёт
следующим; если main уехал, ждёт rebase. Гейту слияния по-прежнему
нужны два одобрения и ноль отказов. Правки, которые исполнитель оставил
без коммита, обёртка кресла коммитит на ветке акта: автор — голос,
коммиттер — обёртка; гейт ревизует ветку, и работа вне коммита была бы
для него невидима. Симлинки и файлы, похожие на секреты (`.env`, ключи,
credentials), в этот коммит не попадают и называются в событии
закрытия; вложенный репозиторий или отвязанный HEAD — отказ от
автокоммита. Выбор акта кресла во вкладке 🔧 показывает его карточку:
стадия, вердикты гейта с полными текстами ревьюеров, диф ветки и кнопки
гейта (ревизия, принять, adopt) — тот же гейт, что в панели coder.

**Новый проект.** Лента одна, но каждое событие несёт свой проект:
окно показывает только события своего проекта (события до появления
поля принадлежат окнам самого стола), и дельта, которую получает
голос, фильтруется так же — новый каталог начинает с пустой ленты и
свежих нитей. Запустите окно в пустом каталоге, и оно положит
каркас: ссылку `.roundtable` на установленный стол и `PROJECT.md` с
описанием проекта — этот файл уходит в пакет каждому голосу одинаково
(правило 1), в отличие от `CLAUDE.md`/`AGENTS.md`, которые прочёл бы
только один CLI. Нити голосов хранятся по проектам: новый каталог
начинает сессии заново, возврат в старый проект возвращает его нити
(Грок и Кими привязывают сессию к рабочему каталогу; нить из другого
каталога не продолжается). Непустой каталог не трогается без
`--init-project`. Быстрый вопрос «случайному» выбирает голос через
`secrets.choice` (энтропия ОС: подстроить нельзя, но и проверить
нельзя — жребий drand остаётся дирижёру); если канал откажет, слово
переходит следующему голосу, а не заканчивает акт. Вкладки вывода
берут список актов из всего журнала проекта (кресло и его ревизии —
одна группа), а кнопка 🪟 открывает монитор окон стола: pid, порт,
проект, время запуска, открыть или остановить. `smoke.sh` работает на
копии журнала; `SMOKE_LIVE=0` пропускает его единственный платный
вызов. Лог CLI исполнителя лежит
рядом с логом акта и переживает закрытие, так что вкладку 🔧 можно
открыть и потом; вкладка следит за новым выводом как терминал (отмотали
вверх — пауза, вернулись вниз — снова следит, клавиши End/Home, кнопка
«↓ новое: N строк»), а идентификатор акта копируется из текстового поля.

## Правила конструкции, которые обеспечивает код

- **Одинаковый вопрос и одинаковый контекст всем** — иначе мнения
  несравнимы.
- **Дословная запись.** Ответ голоса пишется как дан; упавший канал — это
  статус, а не выдуманное мнение.
- **Слепая первая фаза** — единственный барьер против каскада (модель
  смещается к уверенному более раннему ответу).
- **Свойство, объявленное полем журнала, должно быть обеспечено
  механикой** — иначе поле врёт.
- **Молчание — данные**: каждый свод называет, кто спасовал и кого не
  звали.
